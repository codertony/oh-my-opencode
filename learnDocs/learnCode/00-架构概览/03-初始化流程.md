初始化流程位于 OMO 插件的核心层，是插件被 OpenCode 加载时执行的第一阶段。它负责将分散的配置、管理器、工具、钩子等组件组装成一个完整的插件接口。

---

## 核心职责

5 步初始化流程是 OMO 插件的"启动引擎"，其核心职责包括：

1. **配置聚合**：从用户级和项目级两个维度加载配置，执行 3 级合并策略，确保默认配置、用户偏好和项目需求能够正确叠加。

2. **资源初始化**：创建 4 个核心 Manager（TmuxSessionManager、BackgroundManager、SkillMcpManager、ConfigHandler），为后续功能提供基础设施支持。

3. **工具组装**：根据配置条件动态注册 26 个工具，实现功能的按需加载和过滤。

4. **钩子编排**：创建 48 个生命周期钩子，按照 5 层架构组织，形成完整的插件扩展点。

5. **接口暴露**：将组装好的组件注册到 8 个 OpenCode 钩子处理器，使插件能够与 OpenCode 运行时交互。

这个流程的设计遵循"配置驱动、按需组装、分层解耦"的原则，确保插件既功能丰富又保持轻量。

## 5 步初始化流程详解

### Step 1: loadPluginConfig() - 配置加载

**位置**：`src/plugin-config.ts:161-213`

配置加载是初始化的第一步，负责从文件系统读取并合并配置。它实现了 3 级配置合并策略：

```
配置优先级（高 → 低）：
┌─────────────────────────────────────────┐
│  Level 1: Project 配置                   │
│  .opencode/oh-my-opencode.jsonc         │
├─────────────────────────────────────────┤
│  Level 2: User 配置                      │
│  ~/.config/opencode/oh-my-opencode.jsonc │
├─────────────────────────────────────────┤
│  Level 3: 默认值 (Zod Schema)            │
│  src/config/schema/                     │
└─────────────────────────────────────────┘
```

**关键逻辑**：

1. **文件检测**：优先检测 `.jsonc` 格式，支持 JSONC 注释和尾随逗号
2. **配置合并**：使用 `mergeConfigs()` 函数（行 112-159）执行深度合并
   - `agents` 和 `categories`：递归深度合并
   - `disabled_*` 数组：Set 去重合并
   - 其他字段：直接覆盖
3. **Zod 验证**：使用 `OhMyOpenCodeConfigSchema.safeParse()` 验证配置
4. **配置迁移**：自动处理旧版配置键名迁移

**代码片段**：

```typescript
// src/plugin-config.ts:161-213
export function loadPluginConfig(
  directory: string,
  ctx: unknown
): OhMyOpenCodeConfig {
  // 用户级配置路径
  const configDir = getOpenCodeConfigDir({ binary: "opencode" });
  const userDetected = detectPluginConfigFile(configDir);
  const userConfigPath =
    userDetected.format !== "none"
      ? userDetected.path
      : path.join(configDir, "oh-my-opencode.json");

  // 项目级配置路径
  const projectBasePath = path.join(directory, ".opencode");
  const projectDetected = detectPluginConfigFile(projectBasePath);
  const projectConfigPath =
    projectDetected.format !== "none"
      ? projectDetected.path
      : path.join(projectBasePath, "oh-my-opencode.json");

  // 加载用户配置（作为基础）
  let config: OhMyOpenCodeConfig =
    loadConfigFromPath(userConfigPath, ctx) ?? {};

  // 使用项目配置覆盖
  const projectConfig = loadConfigFromPath(projectConfigPath, ctx);
  if (projectConfig) {
    config = mergeConfigs(config, projectConfig);
  }

  return config;
}
```

### Step 2: createManagers() - Manager 创建

**位置**：`src/create-managers.ts:22-92`

Manager 创建阶段初始化 4 个核心管理器，为插件提供基础设施服务：

| Manager | 职责 | 关键功能 |
|---------|------|----------|
| `TmuxSessionManager` | Tmux 会话管理 | 子代理会话创建、清理、布局管理 |
| `BackgroundManager` | 后台任务管理 | 并行代理执行、任务队列、通知 |
| `SkillMcpManager` | Skill MCP 管理 | 技能嵌入式 MCP 服务器的生命周期 |
| `ConfigHandler` | 配置处理 | OpenCode 配置钩子响应 |

**关键逻辑**：

1. **TmuxSessionManager**：初始化时标记服务器运行状态，注册进程清理回调
2. **BackgroundManager**：接收 `tmuxConfig` 和回调函数，建立与 Tmux 的集成
3. **SkillMcpManager**：简单的无状态管理器实例化
4. **ConfigHandler**：创建配置处理器，响应 OpenCode 的配置请求

**代码片段**：

```typescript
// src/create-managers.ts:22-92
export function createManagers(args: {
  ctx: PluginContext
  pluginConfig: OhMyOpenCodeConfig
  tmuxConfig: TmuxConfig
  modelCacheState: ModelCacheState
  backgroundNotificationHookEnabled: boolean
}): Managers {
  const { ctx, pluginConfig, tmuxConfig, modelCacheState, backgroundNotificationHookEnabled } = args

  markServerRunningInProcess()
  const tmuxSessionManager = new TmuxSessionManager(ctx, tmuxConfig)

  registerManagerForCleanup({
    shutdown: async () => {
      await tmuxSessionManager.cleanup().catch((error) => {
        log("[create-managers] tmux cleanup error during process shutdown:", error)
      })
    },
  })

  const backgroundManager = new BackgroundManager(
    ctx,
    pluginConfig.background_task,
    {
      tmuxConfig,
      onSubagentSessionCreated: async (event: SubagentSessionCreatedEvent) => {
        // 子代理会话创建回调
        await tmuxSessionManager.onSessionCreated({...})
      },
      onShutdown: async () => {
        await tmuxSessionManager.cleanup()
      },
      enableParentSessionNotifications: backgroundNotificationHookEnabled,
    },
  )

  initTaskToastManager(ctx.client)

  const skillMcpManager = new SkillMcpManager()

  const configHandler = createConfigHandler({
    ctx: { directory: ctx.directory, client: ctx.client },
    pluginConfig,
    modelCacheState,
  })

  return {
    tmuxSessionManager,
    backgroundManager,
    skillMcpManager,
    configHandler,
  }
}
```

// src/create-hooks.ts:28-87
export function createHooks(args: {
  ctx: PluginContext
  pluginConfig: OhMyOpenCodeConfig
  modelCacheState: ModelCacheState
  backgroundManager: BackgroundManager
  isHookEnabled: (hookName: HookName) => boolean
  safeHookEnabled: boolean
  mergedSkills: LoadedSkill[]
  availableSkills: AvailableSkill[]
}) {
  const {
    ctx,
    pluginConfig,
    modelCacheState,
    backgroundManager,
    isHookEnabled,
    safeHookEnabled,
    mergedSkills,
    availableSkills,
  } = args

  // 创建核心钩子（39 个）
  const core = createCoreHooks({
    ctx,
    pluginConfig,
    modelCacheState,
    isHookEnabled,
    safeHookEnabled,
  })

  // 创建延续钩子（7 个）
  const continuation = createContinuationHooks({
    ctx,
    pluginConfig,
    isHookEnabled,
    safeHookEnabled,
    backgroundManager,
    sessionRecovery: core.sessionRecovery,
  })

  // 创建技能钩子（2 个）
  const skill = createSkillHooks({
    ctx,
    pluginConfig,
    isHookEnabled,
    safeHookEnabled,
    mergedSkills,
    availableSkills,
  })

  // 合并所有钩子
  const hooks = {
    ...core,
    ...continuation,
    ...skill,
  }

  return {
    ...hooks,
    disposeHooks: (): void => {
      disposeCreatedHooks(hooks)
    },
  }
}

### Step 5: createPluginInterface() - OpenCode 接口

**位置**：`src/plugin-interface.ts:16-78`

最后一步将组装好的组件注册到 8 个 OpenCode 钩子处理器，使插件能够与 OpenCode 运行时交互。

**8 个 OpenCode 钩子处理器**：

| 处理器 | 用途 | 对应 OMO 组件 |
|--------|------|---------------|
| `config` | 配置提供 | `managers.configHandler` |
| `tool` | 工具注册 | `tools` |
| `chat.message` | 首消息处理 | `createChatMessageHandler()` |
| `chat.params` | 参数调整 | `createChatParamsHandler()` |
| `chat.headers` | 请求头注入 | `createChatHeadersHandler()` |
| `event` | 事件处理 | `createEventHandler()` |
| `tool.execute.before` | 工具执行前 | `createToolExecuteBeforeHandler()` |
| `tool.execute.after` | 工具执行后 | `createToolExecuteAfterHandler()` |

**代码片段**：

```typescript
// src/plugin-interface.ts:16-78
export function createPluginInterface(args: {
  ctx: PluginContext
  pluginConfig: OhMyOpenCodeConfig
  firstMessageVariantGate: {...}
  managers: Managers
  hooks: CreatedHooks
  tools: ToolsRecord
}): PluginInterface {
  const { ctx, pluginConfig, firstMessageVariantGate, managers, hooks, tools } = args

  return {
    tool: tools,

    "chat.params": async (input: unknown, output: unknown) => {
      const handler = createChatParamsHandler({
        anthropicEffort: hooks.anthropicEffort,
        client: ctx.client,
      })
      await handler(input, output)
    },

    "chat.headers": createChatHeadersHandler({ ctx }),

    "chat.message": createChatMessageHandler({
      ctx,
      pluginConfig,
      firstMessageVariantGate,
      hooks,
    }),

    "experimental.chat.messages.transform": createMessagesTransformHandler({ hooks }),

    "experimental.chat.system.transform": createSystemTransformHandler(),

    config: managers.configHandler,

    event: createEventHandler({
      ctx,
      pluginConfig,
      firstMessageVariantGate,
      managers,
      hooks,
    }),

    "tool.execute.before": createToolExecuteBeforeHandler({ ctx, hooks }),

    "tool.execute.after": createToolExecuteAfterHandler({ ctx, hooks }),
  }
}
```

// src/index.ts:20-111
const OhMyOpenCodePlugin: Plugin = async (ctx) => {
  // 初始化配置上下文
  initConfigContext("opencode", null)
  log("[OhMyOpenCodePlugin] ENTRY - plugin loading", {
    directory: ctx.directory,
  })

  injectServerAuthIntoClient(ctx.client)
  startTmuxCheck()
  await activePluginDispose?.()

  // Step 1: 加载配置
  const pluginConfig = loadPluginConfig(ctx.directory, ctx)
  const disabledHooks = new Set(pluginConfig.disabled_hooks ?? [])
  const isHookEnabled = (hookName: HookName): boolean => !disabledHooks.has(hookName)
  const safeHookEnabled = pluginConfig.experimental?.safe_hook_creation ?? true

  const firstMessageVariantGate = createFirstMessageVariantGate()

  const tmuxConfig = {
    enabled: pluginConfig.tmux?.enabled ?? false,
    layout: pluginConfig.tmux?.layout ?? "main-vertical",
    main_pane_size: pluginConfig.tmux?.main_pane_size ?? 60,
    main_pane_min_width: pluginConfig.tmux?.main_pane_min_width ?? 120,
    agent_pane_min_width: pluginConfig.tmux?.agent_pane_min_width ?? 40,
  }

  const modelCacheState = createModelCacheState()

  // Step 2: 创建 Managers
  const managers = createManagers({
    ctx,
    pluginConfig,
    tmuxConfig,
    modelCacheState,
    backgroundNotificationHookEnabled: isHookEnabled("background-notification"),
  })

  // Step 3: 创建 Tools
  const toolsResult = await createTools({
    ctx,
    pluginConfig,
    managers,
  })

  // Step 4: 创建 Hooks
  const hooks = createHooks({
    ctx,
    pluginConfig,
    modelCacheState,
    backgroundManager: managers.backgroundManager,
    isHookEnabled,
    safeHookEnabled,
    mergedSkills: toolsResult.mergedSkills,
    availableSkills: toolsResult.availableSkills,
  })

  // 创建 Dispose 处理器
  const dispose = createPluginDispose({
    backgroundManager: managers.backgroundManager,
    skillMcpManager: managers.skillMcpManager,
    disposeHooks: hooks.disposeHooks,
  })

  // Step 5: 创建 PluginInterface
  const pluginInterface = createPluginInterface({
    ctx,
    pluginConfig,
    firstMessageVariantGate,
    managers,
    hooks,
    tools: toolsResult.filteredTools,
  })

  activePluginDispose = dispose

  return {
    name: "oh-my-openagent",
    ...pluginInterface,
    // ... 其他实验性功能
  }
}

## 依赖关系

初始化流程的依赖关系遵循严格的顺序：

```
依赖顺序（必须按此顺序执行）：

Step 1 (Config)
    │
    ▼
Step 2 (Managers) ──→ 依赖 pluginConfig
    │
    ▼
Step 3 (Tools) ─────→ 依赖 pluginConfig, managers
    │
    ▼
Step 4 (Hooks) ─────→ 依赖 pluginConfig, managers, toolsResult
    │
    ▼
Step 5 (Interface) ─→ 依赖 pluginConfig, managers, hooks, tools

关键依赖说明：
• Managers 需要 Config 中的 tmux 和 background_task 配置
• Tools 需要 Managers 中的 backgroundManager 和 skillMcpManager
• Hooks 需要 Tools 中的 mergedSkills 和 availableSkills
• Interface 需要所有前置步骤的输出
```

## 故障分析：如果某步失败会怎样？

### 场景：Step 1 配置加载失败

**故障表现**：
当 `loadPluginConfig()` 无法读取或解析配置文件时，会抛出异常或返回部分配置。

**影响范围**：

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1 失败的影响链                                         │
├─────────────────────────────────────────────────────────────┤
│  1. 配置加载失败 → 使用空配置或部分配置                      │
│     ↓                                                        │
│  2. Step 2 (Managers) 使用默认配置创建                       │
│     - Tmux 可能未启用                                        │
│     - Background 任务使用默认并发设置                        │
│     ↓                                                        │
│  3. Step 3 (Tools) 可能加载错误的技能配置                    │
│     ↓                                                        │
│  4. Step 4 (Hooks) 可能启用/禁用错误的钩子                   │
│     ↓                                                        │
│  5. 插件以降级模式运行，部分功能不可用                        │
└─────────────────────────────────────────────────────────────┘
```

**恢复策略**：

1. **部分配置加载**：`parseConfigPartially()` 函数（行 25-67）会尝试加载有效的配置部分，跳过无效部分
2. **错误记录**：`addConfigLoadError()` 记录配置错误，供后续诊断
3. **默认值回退**：Zod Schema 为所有字段提供默认值，确保最小可用性

**代码中的容错处理**：

```typescript
// src/plugin-config.ts:80-102
const result = OhMyOpenCodeConfigSchema.safeParse(rawConfig);

if (result.success) {
  return result.data;
}

// 验证失败时，尝试部分加载
const partialResult = parseConfigPartially(rawConfig);
if (partialResult) {
  log(`Partial config loaded from ${configPath}`, {...});
  return partialResult;
}

// 完全失败时返回 null，调用方使用空对象
return null;
```

**用户可见症状**：
- 插件加载时控制台显示配置错误警告
- 某些代理或工具未按预期启用
- 自定义配置未生效

**修复步骤**：
1. 检查配置文件语法（JSONC 格式）
2. 运行 `bunx oh-my-opencode doctor` 诊断配置问题
3. 参考错误日志修复具体配置项
