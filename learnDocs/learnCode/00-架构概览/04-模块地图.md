模块地图是理解 Oh My OpenCode 代码库的导航图。它展示了 9 大源码目录的结构、职责和相互关系，帮助开发者快速定位代码位置。

---

## 核心职责

源码模块地图是 Oh My OpenCode 架构文档系列的核心组成部分，提供以下功能：

**1. 目录导航**：清晰展示 9 大源码目录的层级结构和文件分布，包括 agents（70 个文件）、hooks（474 个文件）、tools（253 个文件）、features（235 个文件）、config（33 个文件）、shared（185 个文件）、mcp（7 个文件）、plugin（45 个文件）和 plugin-handlers（24 个文件）。

**2. 职责划分**：每个目录都有明确的单一职责。例如，agents 目录负责 11 个 AI Agent 的定义和配置；tools 目录实现 26 个供 Agent 调用的工具；hooks 目录管理 48 个生命周期钩子。

**3. 依赖可视化**：通过 ASCII 图展示模块间的依赖流向，帮助理解代码调用链和数据流向。

**4. 快速定位**：提供代码索引表，按功能点索引到具体文件路径、行号和函数，实现分钟级代码定位。

使用本模块地图时，建议先浏览目录结构了解整体布局，然后根据需求查阅具体目录的详细说明，最后通过代码索引表精确定位到目标代码。

## 9 大源码目录详解

### 1. src/agents/ - Agent 实现

**文件数**：约 70 个 TypeScript 文件

**核心职责**：定义 11 个 AI Agent 的工厂函数、配置和模式。每个 Agent 遵循 `createXXXAgent(model) → AgentConfig` 模式，支持 primary、subagent、all 三种模式。

**关键文件**：
- `sisyphus.ts` - 主协调 Agent，559 行，负责规划、委托和驱动任务完成
- `hephaestus.ts` - 深度工作 Agent，507 行，自主探索代码库并端到端执行
- `oracle.ts` - 只读咨询 Agent，用于架构和调试咨询
- `librarian.ts` - 外部文档和代码搜索 Agent
- `builtin-agents.ts` - Agent 注册表，统一创建所有内置 Agent

### 2. src/hooks/ - 钩子系统

**文件数**：约 474 个 TypeScript 文件

**核心职责**：实现 48 个生命周期钩子，按三层架构组织：Core(39) + Continuation(7) + Skill(2)。每个钩子遵循 `createXXXHook(deps) → HookFunction` 工厂模式。

**关键文件**：
- `atlas/index.ts` - 主协调钩子，757 行，管理 boulder 会话
- `todo-continuation-enforcer/index.ts` - Boulder 机制，强制完成待办
- `ralph-loop/index.ts` - 自引用开发循环，14 个文件
- `keyword-detector/index.ts` - 模式检测（ultrawork/search/analyze）
- `index.ts` - 钩子聚合和注册入口

### 3. src/tools/ - 工具实现

**文件数**：约 253 个 TypeScript 文件

**核心职责**：实现 26 个供 Agent 调用的工具，分布在 15 个子目录。包括任务管理、代码搜索、LSP 重构、会话管理等类别。

**关键文件**：
- `delegate-task/index.ts` - 任务委托工具，创建子 Agent 任务
- `lsp/index.ts` - LSP 工具集，6 个重构工具（跳转定义、查找引用、重命名等）
- `ast-grep/index.ts` - AST 感知代码搜索和替换
- `session-manager/index.ts` - 会话历史管理工具
- `look-at/index.ts` - 多模态文件分析（PDF/图片）

### 4. src/features/ - 功能模块

**文件数**：约 235 个 TypeScript 文件

**核心职责**：19 个独立功能模块，包括后台 Agent、Tmux 集成、MCP OAuth、技能加载器等。每个模块是自包含的独立单元。

**关键文件**：
- `background-agent/index.ts` - 后台 Agent 管理器，支持并行执行
- `tmux-subagent/index.ts` - Tmux 会话管理集成
- `skill-mcp-manager/index.ts` - 技能嵌入式 MCP 管理
- `builtin-skills/index.ts` - 内置技能（git-master、playwright 等）
- `context-injector/index.ts` - AGENTS.md 自动注入

### 5. src/config/ - 配置 Schema

**文件数**：约 33 个 TypeScript 文件

**核心职责**：Zod v4 Schema 系统，24 个 Schema 文件组成 `OhMyOpenCodeConfigSchema`。支持多级配置合并（用户级 + 项目级）。

**关键文件**：
- `schema/oh-my-opencode-config.ts` - 根 Schema，28 个配置字段
- `schema/agent-overrides.ts` - Agent 覆盖配置，21 个字段
- `schema/categories.ts` - 8 个内置类别 + 自定义类别
- `schema/hooks.ts` - 48 个钩子名称定义
- `index.ts` - Schema 导出入口

### 6. src/shared/ - 工具函数

**文件数**：约 185 个 TypeScript 文件（Metis 识别 95+ 核心文件）

**核心职责**：跨模块共享的实用函数，分为 13 个类别。通过 `index.ts` 统一导出，Logger 写入 `/tmp/oh-my-opencode.log`。

**关键文件**：
- `model-resolver.ts` - 模型解析，4 步流程
- `tmux/index.ts` - Tmux 集成，11 个相关文件
- `logger.ts` - 日志记录，62 处引用
- `data-path.ts` - XDG 存储路径解析
- `frontmatter.ts` - YAML 元数据提取

### 7. src/mcp/ - MCP 集成

**文件数**：约 7 个 TypeScript 文件

**核心职责**：三层 MCP 系统的第一层，3 个内置远程 HTTP MCP：websearch（Exa/Tavily）、context7（官方文档）、grep_app（GitHub 搜索）。

**关键文件**：
- `index.ts` - `createBuiltinMcps()` 工厂函数
- `websearch.ts` - Exa/Tavily 搜索配置
- `context7.ts` - Context7 文档 MCP
- `grep-app.ts` - Grep.app GitHub 代码搜索
- `types.ts` - MCP 名称 Schema

### 8. src/plugin/ - 插件处理器

**文件数**：约 45 个 TypeScript 文件

**核心职责**：8 个 OpenCode 钩子处理器，组装 48 个钩子到 PluginInterface。每个处理器文件对应一个 OpenCode 钩子类型。

**关键文件**：
- `tool-registry.ts` - 工具注册表，组装 26 个工具
- `chat-message.ts` - 首消息变体和关键词检测
- `event.ts` - 会话生命周期管理
- `tool-execute-before.ts` - 工具执行前守卫
- `tool-execute-after.ts` - 工具执行后处理
- `hooks/` - 钩子组合子目录

### 9. src/plugin-handlers/ - 配置处理器

**文件数**：约 24 个 TypeScript 文件

**核心职责**：6 阶段配置加载管道，实现 `config` 钩子处理器。按顺序注册 Agent、工具、MCP 和命令。

**关键文件**：
- `config-handler.ts` - 主协调器，6 阶段顺序执行
- `agent-config-handler.ts` - Agent 配置，5 个来源加载
- `tool-config-handler.ts` - 工具权限配置
- `mcp-config-handler.ts` - MCP 合并（内置 + CC + 插件）
- `command-config-handler.ts` - 命令配置，9 个并行来源

## 关键代码片段

### 片段 1：插件入口点（src/index.ts）

```typescript
const OhMyOpenCodePlugin: Plugin = async (ctx) => {
  // 初始化配置上下文
  initConfigContext("opencode", null)
  log("[OhMyOpenCodePlugin] ENTRY - plugin loading", {
    directory: ctx.directory,
  })

  // 5 步初始化流程
  const pluginConfig = loadPluginConfig(ctx.directory, ctx)
  const managers = createManagers({ ctx, pluginConfig, ... })
  const toolsResult = await createTools({ ctx, pluginConfig, managers })
  const hooks = createHooks({ ctx, pluginConfig, managers, ... })
  const pluginInterface = createPluginInterface({ ctx, pluginConfig, managers, hooks, tools })

  return {
    name: "oh-my-openagent",
    ...pluginInterface,
  }
}
```

### 片段 2：工具注册表（src/plugin/tool-registry.ts）

export function createToolRegistry(args: {
  ctx: PluginContext
  pluginConfig: OhMyOpenCodeConfig
  managers: Managers
  skillContext: SkillContext
  availableCategories: AvailableCategory[]

  // 创建各类工具

## 依赖关系

**核心依赖原则**：

1. **shared/ 和 config/ 是基础层**：被所有其他模块依赖，自身不依赖业务模块
2. **agents/ 和 tools/ 是核心层**：相互独立，都依赖 shared/ 和 config/
3. **plugin/ 是组装层**：依赖 agents/、tools/、hooks/，组装成 OpenCode 接口
4. **features/ 是功能层**：提供独立功能，可被 tools/ 和 hooks/ 使用
5. **mcp/ 是集成层**：提供外部 MCP 服务，被 plugin/ 集成

**依赖禁止**：
- 禁止循环依赖
- 禁止底层模块依赖上层模块（如 shared/ 不能依赖 plugin/）
- 禁止跨模块直接引用（应通过 index.ts 导出）

## 实战示例：定位代码位置

**场景**：需要修改 Sisyphus Agent 的模型回退链

**步骤 1**：确定目录
- 这是 Agent 相关功能，应该在 `src/agents/` 目录

**步骤 2**：查找关键文件
- 查看 `src/agents/index.ts` 导出，发现 `createBuiltinAgents`
- 查看 `src/agents/builtin-agents.ts`，找到 Sisyphus Agent 创建逻辑

**步骤 3**：定位模型配置
- 发现模型配置在 `src/agents/sisyphus.ts`
- 但回退链定义在 `src/shared/model-requirements.ts`

**步骤 4**：验证修改
- 修改 `src/shared/model-requirements.ts` 中的 `AGENT_MODEL_REQUIREMENTS`
- 运行测试验证回退链正确性

**耗时**：约 3 分钟完成定位
