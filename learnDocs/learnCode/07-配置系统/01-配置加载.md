配置加载系统位于插件架构的第三层（Layer 3），负责从多个来源加载、合并和验证用户配置，最终生成统一的配置对象供下层组件使用。

---

## 核心职责

配置加载系统承担以下核心职责：

1. **多源配置加载**：从用户目录（`~/.config/opencode/`）和项目目录（`.opencode/`）分别加载配置文件，支持 JSON 和 JSONC 两种格式。

2. **智能合并策略**：采用深度合并（deep merge）策略处理嵌套对象，对于 `disabled_*` 数组字段使用 Set 并集而非简单覆盖，确保用户和项目的禁用列表都能生效。

3. **JSONC 解析支持**：支持带注释和尾随逗号的 JSONC 格式，提升配置可读性和可维护性。

4. **配置迁移**：自动检测并迁移旧版本配置（如重命名的 agent、hook 和模型版本），保证向后兼容性。

5. **Zod 验证**：使用 Zod v4 进行严格的类型验证，无效字段会被记录但不会阻止插件启动（部分加载模式）。

## 3 级配置加载

### 1. 用户配置 (~/.config/opencode/)

用户级配置存储在用户主目录下的 `.config/opencode/` 目录中，文件名为 `oh-my-opencode.json` 或 `oh-my-opencode.jsonc`（优先使用 `.jsonc`）。

**代码位置**：`src/plugin-config.ts` 第 166-171 行

```typescript
// 用户级配置路径 - 优先使用 .jsonc 而非 .json
const configDir = getOpenCodeConfigDir({ binary: "opencode" });
const userDetected = detectPluginConfigFile(configDir);
const userConfigPath =
  userDetected.format !== "none"
    ? userDetected.path
    : path.join(configDir, "oh-my-opencode.json");
```

**用途**：
- 存储用户全局偏好设置
- 定义跨项目的默认 agent 配置
- 设置个人禁用列表（`disabled_agents` 等）

### 2. 项目配置 (.opencode/)

项目级配置位于当前工作目录的 `.opencode/` 子目录中，同样支持 `.json` 和 `.jsonc` 两种扩展名。

**代码位置**：`src/plugin-config.ts` 第 179-184 行

```typescript
// 项目级配置路径 - 优先使用 .jsonc 而非 .json
const projectBasePath = path.join(directory, ".opencode");
const projectDetected = detectPluginConfigFile(projectBasePath);
const projectConfigPath =
  projectDetected.format !== "none"
    ? projectDetected.path
    : path.join(projectBasePath, "oh-my-opencode.json");
```

**用途**：
- 覆盖用户级配置，实现项目特定设置
- 定义项目专用的 agent 覆盖
- 配置项目特定的类别（categories）

### 3. 默认配置

默认配置由 Zod Schema 的 `.optional()` 字段和默认值提供。当用户和项目配置都未指定某个字段时，Zod 的 `safeParse()` 会自动填充默认值。

**代码位置**：`src/config/schema/oh-my-opencode-config.ts` 第 26-73 行

```typescript
export const OhMyOpenCodeConfigSchema = z.object({
  $schema: z.string().optional(),
  new_task_system_enabled: z.boolean().optional(),
  default_run_agent: z.string().optional(),
  disabled_mcps: z.array(AnyMcpNameSchema).optional(),
  // ... 其他字段均为 optional
});
```

**用途**：
- 提供所有配置字段的默认值
- 确保配置对象结构完整
- 通过 Zod 验证保证类型安全

## 深度合并策略

配置合并采用差异化的合并策略，根据字段类型选择不同的合并方式：

### 递归深度合并（对象字段）

对于 `agents`、`categories`、`claude_code` 等对象字段，使用递归深度合并：

```typescript
// src/plugin-config.ts 第 119-120 行
agents: deepMerge(base.agents, override.agents),
categories: deepMerge(base.categories, override.categories),
claude_code: deepMerge(base.claude_code, override.claude_code),
```

**行为**：
- 嵌套对象递归合并
- 子属性被覆盖，兄弟属性保留
- 数组字段被替换（非拼接）

### Set 并集（数组字段）

对于 `disabled_*` 系列数组字段，使用 Set 并集：

```typescript
// src/plugin-config.ts 第 121-126 行
disabled_agents: [
  ...new Set([
    ...(base.disabled_agents ?? []),
    ...(override.disabled_agents ?? []),
  ]),
],
```

**行为**：
- 用户和项目的禁用列表合并
- 自动去重
- 任一配置中禁用的项目都会被禁用

### 直接覆盖（其他字段）

对于其他简单字段，项目配置直接覆盖用户配置：

```typescript
// src/plugin-config.ts 第 116-118 行
return {
  ...base,
  ...override,
  // 特殊字段使用上述合并策略
};
```

## 配置加载流程

配置加载遵循以下流程：

1. **路径检测**：检测用户和项目配置文件路径，优先使用 `.jsonc` 格式
2. **遗留配置迁移**：如果检测到旧命名（`oh-my-opencode.json` 等），自动复制到新命名
3. **用户配置加载**：先加载用户级配置作为基础
4. **项目配置加载**：加载项目级配置并合并到用户配置
5. **Zod 验证**：使用 `safeParse()` 验证合并后的配置
6. **部分加载**：如果验证失败，尝试部分加载有效字段
7. **返回配置**：返回最终的 `OhMyOpenCodeConfig` 对象

### 片段 1：配置合并核心逻辑

```typescript
// src/plugin-config.ts 第 112-159 行
export function mergeConfigs(
  base: OhMyOpenCodeConfig,
  override: OhMyOpenCodeConfig
): OhMyOpenCodeConfig {
  return {
    ...base,
    ...override,
    agents: deepMerge(base.agents, override.agents),
    categories: deepMerge(base.categories, override.categories),
    disabled_agents: [
      ...new Set([
        ...(base.disabled_agents ?? []),
        ...(override.disabled_agents ?? []),
      ]),
    ],
    // ... 其他 disabled_* 字段类似处理
    claude_code: deepMerge(base.claude_code, override.claude_code),
  };
}
```

### 片段 2：深度合并实现

```typescript
// src/shared/deep-merge.ts 第 23-53 行
export function deepMerge<T extends Record<string, unknown>>(
  base: T | undefined,
  override: T | undefined,
  depth = 0
): T | undefined {
  if (!base && !override) return undefined;
  if (!base) return override;
  if (!override) return base;
  if (depth > MAX_DEPTH) return override ?? base;

  const result = { ...base } as Record<string, unknown>;

  for (const key of Object.keys(override)) {
    if (DANGEROUS_KEYS.has(key)) continue;
    const baseValue = base[key];
    const overrideValue = override[key];
    if (overrideValue === undefined) continue;

    if (isPlainObject(baseValue) && isPlainObject(overrideValue)) {
      result[key] = deepMerge(baseValue, overrideValue, depth + 1);
    } else {
      result[key] = overrideValue;
    }
  }
  return result as T;
}
```

## 实战示例

### 示例 1: 配置覆盖

**场景**：用户全局配置禁用 `hephaestus` agent，但某个项目需要启用它。

**用户配置** (`~/.config/opencode/oh-my-opencode.jsonc`):
```jsonc
{
  "disabled_agents": ["hephaestus"],
  "agents": {
    "sisyphus": {
      "model": "claude-opus-4-6"
    }
  }
}
```

**项目配置** (`.opencode/oh-my-opencode.jsonc`):
```jsonc
{
  // 覆盖用户配置，启用 hephaestus
  "disabled_agents": [],
  "agents": {
    "sisyphus": {
      "model": "kimi-k2.5"  // 覆盖用户配置的模型
    },
    "hephaestus": {
      "model": "gpt-5.4"
    }
  }
}
```

**最终合并结果**:
```jsonc
{
  "disabled_agents": ["hephaestus"],  // Set 并集后仍包含 hephaestus
  // 注意：如需完全启用，项目配置应使用其他机制
  "agents": {
    "sisyphus": {
      "model": "kimi-k2.5",  // 项目配置覆盖
      // 其他属性来自用户配置
    },
    "hephaestus": {
      "model": "gpt-5.4"  // 项目配置新增
    }
  }
}
```

### 示例 2: 数组并集

**场景**：用户和项目分别禁用不同的 MCP。

**用户配置**:
```jsonc
{
  "disabled_mcps": ["websearch", "context7"]
}
```

**项目配置**:
```jsonc
{
  "disabled_mcps": ["websearch", "grep_app"]
}
```

**合并结果**:
```jsonc
{
  "disabled_mcps": ["websearch", "context7", "grep_app"]
  // websearch 去重，context7 和 grep_app 都保留
}
```

这种设计确保用户和项目的禁用设置都能生效，避免项目配置意外启用用户明确禁用的功能。
