## 核心职责

配置处理器（Config Handler）是 oh-my-opencode 插件的中央配置编排器，承担以下核心职责：

**配置整合**：将用户级配置（`~/.config/opencode/`）、项目级配置（`.opencode/`）和插件默认配置进行深度合并，确保多层配置的优先级和继承关系正确处理。

**组件注册**：按顺序注册 Provider、Agent、Tool、MCP 和 Command 五大类组件，每个阶段都有明确的依赖关系和执行顺序。

**错误隔离**：在 Phase 2 的插件加载过程中，使用超时机制和错误捕获确保单个插件的失败不会影响整体配置流程。

**权限控制**：为不同 Agent 分配特定的工具权限，实现最小权限原则，例如 Librarian 拥有 `grep_app_*` 权限而其他 Agent 默认拒绝。

**配置转换**：处理配置键名映射、Agent 优先级排序、Plan 降级等复杂的配置转换逻辑。

## 6 阶段配置管线

### Phase 1: Provider

Provider 阶段负责处理模型提供商配置，主要任务包括：

- **上下文限制缓存**：遍历所有 Provider 的模型配置，将 `context` 限制值缓存到 `modelContextLimitsCache`
- **视觉能力检测**：通过检查 `modalities.input` 或 `capabilities.input.image` 识别支持图像输入的模型
- **Anthropic Beta 头检测**：检测 `anthropic-beta` 头中是否包含 `context-1m` 以启用 1M 上下文

```typescript
// src/plugin-handlers/provider-config-handler.ts:29-73
export function applyProviderConfig(params: {
  config: Record<string, unknown>;
  modelCacheState: ModelCacheState;
}): void {
  const providers = params.config.provider as
    | Record<string, ProviderConfig>
    | undefined;
  const modelContextLimitsCache = params.modelCacheState.modelContextLimitsCache;

  modelContextLimitsCache.clear();

  // 检测 anthropic-beta 头
  const anthropicBeta = providers?.anthropic?.options?.headers?.["anthropic-beta"];
  params.modelCacheState.anthropicContext1MEnabled =
    anthropicBeta?.includes("context-1m") ?? false;

  // 缓存视觉能力模型
  for (const [providerID, providerConfig] of Object.entries(providers)) {
    const models = providerConfig?.models;
    if (!models) continue;

    for (const [modelID, modelConfig] of Object.entries(models)) {
      if (supportsImageInput(modelConfig)) {
        visionCapableModelsCache.set(
          `${providerID}/${modelID}`,
          { providerID, modelID },
        );
      }
      // 缓存上下文限制...
    }
  }
}
```

### Phase 2: Plugin-components

第二阶段加载 Claude Code 插件组件，采用超时机制和错误隔离策略：

- **超时控制**：默认 10 秒超时（可通过 `experimental.plugin_load_timeout_ms` 配置）
- **错误隔离**：单个插件加载失败不会阻断其他插件
- **组件收集**：收集插件提供的 commands、skills、agents、mcpServers、hooksConfigs

```typescript
// src/plugin-handlers/plugin-components-loader.ts:25-70
export async function loadPluginComponents(params: {
  pluginConfig: OhMyOpenCodeConfig;
}): Promise<PluginComponents> {
  const timeoutMs = params.pluginConfig.experimental?.plugin_load_timeout_ms ?? 10000;

  try {
    let timeoutId: ReturnType<typeof setTimeout> | undefined;
    const timeoutPromise = new Promise<never>((_, reject) => {
      timeoutId = setTimeout(
        () => reject(new Error(`Plugin loading timed out after ${timeoutMs}ms`)),
        timeoutMs,
      );
    });

    const pluginComponents = (await Promise.race([
      loadAllPluginComponents({...}),
      timeoutPromise,
    ]).finally(() => {
      if (timeoutId) clearTimeout(timeoutId);
    })) as PluginComponents;

    return pluginComponents;
  } catch (error) {
    // 错误隔离：返回空组件而不是抛出
    addConfigLoadError({ path: "plugin-loading", error: errorMessage });
    return EMPTY_PLUGIN_COMPONENTS;
  }
}
```

### Phase 3: Agents

Agent 配置阶段是最复杂的阶段，从 5 个来源并行加载 Agent 配置：

**配置来源**：
1. 内置 Agent（`createBuiltinAgents`）
2. 用户级 Claude Agent（`loadUserAgents`）
3. 项目级 Claude Agent（`loadProjectAgents`）
4. 插件提供的 Agent（`pluginComponents.agents`）
5. 配置文件中的 Agent（`config.agent`）

**技能发现**：并行发现 7 个来源的技能用于 Agent 感知

**特殊处理**：
- Sisyphus 启用时自动设为默认 Agent
- Plan Agent 降级为子 Agent（当 `replace_plan: true`）
- 受保护 Agent 名称防止被覆盖

```typescript

  includeClaudeSkillsForAwareness ? discoverUserClaudeSkills() : Promise.resolve([]),
  includeClaudeSkillsForAwareness ? discoverProjectClaudeSkills(...) : Promise.resolve([]),
```

### Phase 4: Tools

工具配置阶段为不同 Agent 分配特定的工具权限：

**全局工具禁用**：
- `grep_app_*`：默认禁用（仅 Librarian 允许）
- `task_*` 和 `teammate`：默认禁用（特定 Agent 允许）
- `LspHover` 等 LSP 工具：默认禁用

**Agent 特定权限**：

| Agent | 允许的工具 |
|-------|-----------|
| Librarian | `grep_app_*` |
| Atlas, Sisyphus, Prometheus | `task`, `task_*`, `teammate` |
| Hephaestus | `task` |
| Multimodal-Looker | 禁用 `task` 和 `look_at` |

```typescript
// src/plugin-handlers/tool-config-handler.ts:35-49
params.config.tools = {
  ...(params.config.tools as Record<string, unknown>),
  "grep_app_*": false,  // 默认禁用
  "task_*": false,      // 默认禁用
  teammate: false,      // 默认禁用
  // ...
};

// 为特定 Agent 分配权限
const librarian = agentByKey(params.agentResult, "librarian");
if (librarian) {
  librarian.permission = { ...librarian.permission, "grep_app_*": "allow" };
}
```

### Phase 5: MCPs

MCP 配置阶段合并三层 MCP 配置：

**三层 MCP 系统**：
1. **内置 MCP**（`createBuiltinMcps`）：websearch、context7、grep_app
2. **Claude Code MCP**（`loadMcpConfigs`）：从 `.mcp.json` 加载
3. **插件 MCP**（`pluginComponents.mcpServers`）：CC 插件提供

**合并优先级**：用户配置 > 插件 MCP > CC MCP > 内置 MCP

```typescript
// src/plugin-handlers/mcp-config-handler.ts:41-59
const merged = {
  ...createBuiltinMcps(disabledMcps, params.pluginConfig),  // 基础层
  ...(userMcp ?? {}),                                        // 用户覆盖
  ...mcpResult.servers,                                      // CC 配置
  ...params.pluginComponents.mcpServers,                     // 插件配置
} as Record<string, McpEntry>;

// 应用用户禁用
for (const name of userDisabledMcps) {
  if (merged[name]) {
    merged[name] = { ...merged[name], enabled: false };
  }
}

// 应用插件禁用（完全移除）
const disabledSet = new Set(disabledMcps);
for (const name of disabledSet) {
  delete merged[name];
}
```

命令配置阶段从 9 个并行来源加载命令和技能：

**命令来源**（按优先级从低到高）：
1. 内置命令（`loadBuiltinCommands`）
2. 配置源技能命令
3. 用户命令（`loadUserCommands`）

5. 全局 Agent 技能

8. 系统命令（来自 OpenCode）
9. 项目命令、技能、Agent 技能

## 配置处理流程

配置处理器的执行遵循严格的顺序依赖关系：

1. **Provider 先行**：必须先处理 Provider 配置，因为后续 Agent 配置需要模型信息
2. **插件加载次之**：插件组件需要在 Agent、MCP、Command 加载前完成
3. **Agent 在 Tool 之前**：Tool 配置需要 Agent 结果来分配权限
4. **并行优化**：Phase 3、5、6 内部大量使用 `Promise.all` 并行加载多个来源

## 关键代码片段

### 片段 1：配置处理器主协调器

```typescript
// src/plugin-handlers/config-handler.ts:20-50
export function createConfigHandler(deps: ConfigHandlerDeps) {
  const { ctx, pluginConfig, modelCacheState } = deps;

  return async (config: Record<string, unknown>) => {
    const formatterConfig = config.formatter;

    // Phase 1: Provider 配置
    applyProviderConfig({ config, modelCacheState });
    clearFormatterCache();

    // Phase 2: 插件组件加载
    const pluginComponents = await loadPluginComponents({ pluginConfig });

    // Phase 3: Agent 配置
    const agentResult = await applyAgentConfig({
      config,
      pluginConfig,
      ctx,
      pluginComponents,
    });

    // Phase 4-6: 工具、MCP、命令配置
    applyToolConfig({ config, pluginConfig, agentResult });
    await applyMcpConfig({ config, pluginConfig, pluginComponents });
    await applyCommandConfig({ config, pluginConfig, ctx, pluginComponents });

    // 恢复 formatter 配置
    config.formatter = formatterConfig;

    log("[config-handler] config handler applied", {
      agentCount: Object.keys(agentResult).length,
      commandCount: Object.keys((config.command as Record<string, unknown>) ?? {})
        .length,
    });
  };
}
```

### 片段 2：Agent 优先级排序

```typescript
// src/plugin-handlers/agent-priority-order.ts:3-40
const CORE_AGENT_ORDER: ReadonlyArray<{ displayName: string; order: number }> = [
  { displayName: getAgentDisplayName("sisyphus"), order: 1 },
  { displayName: getAgentDisplayName("hephaestus"), order: 2 },
  { displayName: getAgentDisplayName("prometheus"), order: 3 },
  { displayName: getAgentDisplayName("atlas"), order: 4 },
];

export function reorderAgentsByPriority(
  agents: Record<string, unknown>,
): Record<string, unknown> {
  const ordered: Record<string, unknown> = {};
  const seen = new Set<string>();

  // 首先放置核心 Agent（按优先级顺序）
  for (const { displayName, order } of CORE_AGENT_ORDER) {
    if (Object.prototype.hasOwnProperty.call(agents, displayName)) {
      ordered[displayName] = injectOrderField(agents[displayName], order);
      seen.add(displayName);
    }
  }

  // 然后放置其他 Agent
  for (const [key, value] of Object.entries(agents)) {
    if (!seen.has(key)) {
      ordered[key] = value;
    }
  }

  return ordered;
}
```

### 片段 3：受保护 Agent 名称过滤

```typescript
// src/plugin-handlers/agent-override-protection.ts
export function createProtectedAgentNameSet(
  builtinAgentNames: string[],
): Set<string> {
  return new Set(builtinAgentNames.map(name => name.toLowerCase()));
}

export function filterProtectedAgentOverrides(
  userAgents: Record<string, unknown>,
  protectedNames: Set<string>,
): Record<string, unknown> {
  const filtered: Record<string, unknown> = {};

  for (const [name, config] of Object.entries(userAgents)) {
    const lowerName = name.toLowerCase();
    // 允许完全匹配（大小写敏感）或新名称
    if (!protectedNames.has(lowerName) || protectedNames.has(name)) {
      filtered[name] = config;
    }
  }

  return filtered;
}
```

## 实战示例

### 示例 1: Agent 配置加载

假设用户有以下配置：

```jsonc
// ~/.config/opencode/oh-my-opencode.jsonc
{
  "agents": {
    "sisyphus": {
      "model": "kimi-k2.5",
      "temperature": 0.7
    }
  },
  "disabled_agents": ["hephaestus"],
  "sisyphus_agent": {
    "planner_enabled": true,
    "replace_plan": true
  }
}
```

配置处理器的执行过程：

1. **Phase 1**：检测 Provider 配置，缓存模型限制
2. **Phase 2**：加载 CC 插件（如果有）
3. **Phase 3**：
   - 创建内置 Agent（Sisyphus、Atlas、Librarian 等）
   - 应用用户覆盖：`sisyphus.model = "kimi-k2.5"`
   - 过滤禁用 Agent：移除 Hephaestus
   - 创建 Prometheus（因为 `planner_enabled: true`）
   - 降级 Plan Agent（因为 `replace_plan: true`）
   - 设置 Sisyphus 为默认 Agent
   - 按优先级排序：Sisyphus → Hephaestus（已禁用）→ Prometheus → Atlas
4. **Phase 4**：为 Sisyphus 分配 `task`、`task_*`、`teammate` 权限
5. **Phase 5-6**：加载 MCP 和命令
