横切关注点位于集成工作流层，它们不直接参与业务逻辑，而是为所有组件提供通用服务。这些关注点贯穿整个系统，确保日志记录、错误处理、性能指标和遥测数据的统一收集。

## 核心职责

横切关注点是插件架构中的基础设施组件，负责处理那些跨越多个模块的通用功能。日志系统提供统一的日志记录机制，将日志写入 `/tmp/oh-my-opencode.log` 文件供调试使用。错误处理模块对模型错误进行分类，区分可重试错误和不可重试错误，支持自动降级策略。指标收集跟踪系统性能和工具使用情况。遥测模块收集运行时数据，帮助理解系统行为和优化性能。这些组件通过统一的接口暴露给上层工具、钩子和代理，确保整个系统的一致性和可观测性。

## 横切关注点

### 1. 日志

日志系统是调试和监控的基础。它采用缓冲机制，将日志条目先存入内存缓冲区，然后定期批量写入文件，避免频繁的磁盘 I/O 操作。

**核心机制：**
- 日志文件路径：`/tmp/oh-my-opencode.log`
- 缓冲区大小限制：50 条
- 刷新间隔：500 毫秒
- 自动刷新：当缓冲区满时立即写入

日志函数接收消息字符串和可选的数据对象，自动添加 ISO 格式时间戳，并将数据序列化为 JSON。

### 2. 错误处理

错误处理模块专注于模型相关的错误分类和恢复策略。它将错误分为可重试和不可重试两类，支持智能降级。

**可重试错误类型：**
- `ProviderModelNotFoundError` - 模型未找到
- `RateLimitError` - 速率限制
- `QuotaExceededError` - 配额超限
- `ProviderConnectionError` - 连接错误
- `AuthenticationError` - 认证失败

**不可重试错误类型：**
- `MessageAbortedError` - 消息中止
- `PermissionDeniedError` - 权限拒绝
- `ContextLengthError` - 上下文长度超限
- `TimeoutError` - 超时

### 3. 指标

指标收集模块跟踪系统运行时的关键指标，包括：
- 工具调用次数和成功率
- 模型响应时间
- 降级触发频率
- 会话生命周期事件

这些指标用于性能分析和系统优化，帮助识别瓶颈和改进点。

### 4. 遥测

遥测模块负责收集和上报运行时数据，包括：
- 会话使用统计
- 工具使用模式
- 错误发生频率
- 模型性能数据

遥测数据采用异步收集策略，避免影响主流程性能。

## 横切关注点流程

横切关注点的使用遵循以下流程：

1. **初始化阶段**：系统启动时初始化日志文件路径和缓冲区
2. **运行时阶段**：各组件通过统一接口调用日志、错误处理等功能
3. **错误处理阶段**：当发生错误时，错误分类器判断是否需要降级
4. **降级阶段**：如果需要，选择备用模型提供商并重试
5. **关闭阶段**：刷新日志缓冲区，确保所有日志写入磁盘

### 片段 1：日志记录实现

```typescript
// src/shared/logger.ts:30-42
export function log(message: string, data?: unknown): void {
  try {
    const timestamp = new Date().toISOString()
    const logEntry = `[${timestamp}] ${message} ${data ? JSON.stringify(data) : ""}\n`
    buffer.push(logEntry)
    if (buffer.length >= BUFFER_SIZE_LIMIT) {
      flush()
    } else {
      scheduleFlush()
    }
  } catch {
  }
}
```

### 片段 2：错误分类逻辑

```typescript
// src/shared/model-error-classifier.ts:101-121
export function isRetryableModelError(error: ErrorInfo): boolean {
  if (error.name) {
    const errorNameLower = error.name.toLowerCase()
    if (NON_RETRYABLE_ERROR_NAMES.has(errorNameLower)) {
      return false
    }
    if (RETRYABLE_ERROR_NAMES.has(errorNameLower)) {
      return true
    }
  }

  const msg = error.message?.toLowerCase() ?? ""
  if (hasProviderAutoRetrySignal(msg)) {
    return true
  }
  return RETRYABLE_MESSAGE_PATTERNS.some((pattern) => msg.includes(pattern))
}
```

### 片段 3：安全钩子创建

```typescript
// src/shared/safe-create-hook.ts:7-24
export function safeCreateHook<T>(
  name: string,
  factory: () => T,
  options?: SafeCreateHookOptions,
): T | null {
  const enabled = options?.enabled ?? true

  if (!enabled) {
    return factory() ?? null
  }

  try {
    return factory() ?? null
  } catch (error) {
    log(`[safe-create-hook] Hook creation failed: ${name}`, { error })
    return null
  }
}
```

## 依赖关系

横切关注点模块的依赖关系如下：

- **logger.ts**：无外部依赖，基础模块
- **config-errors.ts**：无外部依赖，纯类型定义
- **model-error-classifier.ts**：依赖 `model-requirements.ts` 和 `connected-providers-cache.ts`
- **safe-create-hook.ts**：依赖 `logger.ts` 进行错误日志记录

这些模块被以下组件广泛使用：
- 所有工具 (Tools)
- 所有钩子 (Hooks)
- 代理管理器 (Agent Managers)
- 配置加载器 (Config Loader)

## 实战示例

### 示例 1: 错误日志记录

当钩子创建失败时，系统会自动记录错误日志并返回 null，避免整个系统崩溃：

```typescript
import { safeCreateHook } from "./shared/safe-create-hook"

// 尝试创建一个可能失败的钩子
const myHook = safeCreateHook(
  "my-custom-hook",
  () => {
    // 可能抛出异常的初始化逻辑
    return createComplexHook()
  },
  { enabled: true }
)

if (myHook === null) {
  console.log("钩子创建失败，但系统继续运行")
}
```

执行后，可以在 `/tmp/oh-my-opencode.log` 中查看错误详情：
```
[2026-03-28T10:30:00.000Z] [safe-create-hook] Hook creation failed: my-custom-hook {"error":"..."}
```

### 示例 2: 遥测数据收集

在模型调用过程中，系统自动收集遥测数据用于性能分析：

```typescript
import { log } from "./shared/logger"
import { isRetryableModelError } from "./shared/model-error-classifier"

async function executeModelCall(model: string, prompt: string) {
  const startTime = Date.now()
  
  try {
    const result = await callModel(model, prompt)
    
    // 记录成功指标
    log("[telemetry] Model call succeeded", {
      model,
      duration: Date.now() - startTime,
      success: true
    })
    
    return result
  } catch (error) {
    // 判断错误类型
    const isRetryable = isRetryableModelError({
      name: error.name,
      message: error.message
    })
    
    // 记录错误遥测
    log("[telemetry] Model call failed", {
      model,
      duration: Date.now() - startTime,
      success: false,
      errorType: error.name,
      isRetryable
    })
    
    throw error
  }
}
```
