工具生命周期位于 Integration 层（Layer 3），是连接核心系统与 OpenCode 运行时的关键桥梁。它管理着从工具注册到最终清理的完整流程，确保每个工具调用都在受控环境中执行。

---

## 核心职责

工具生命周期模块承担着三大核心职责：

**注册管理**：在插件初始化阶段，工具生命周期负责收集和注册所有可用工具。这包括内置工具（如 grep、glob、ast_grep）、动态生成的工具（如 skill 工具、MCP 工具）以及条件性启用的工具（如 task 系统工具、hashline 编辑工具）。注册过程中会进行工具去重、参数模式规范化，并根据配置过滤禁用工具。

**执行编排**：每次工具调用都遵循 "before → execute → after" 的三段式执行模型。Before 阶段运行前置钩子链，用于参数校验、安全检查和上下文注入；Execute 阶段调用实际工具实现；After 阶段运行后置钩子链，处理输出截断、错误恢复和元数据存储。

**资源清理**：工具执行完成后，生命周期模块负责清理临时资源、释放会话状态、存储执行元数据，确保系统资源得到正确回收，为下一次调用做好准备。

## 工具生命周期阶段

### 1. 注册

工具注册发生在插件初始化阶段，由 `createToolRegistry` 函数负责。注册流程如下：

```typescript
// src/plugin/tool-registry.ts:136-151
const allTools: Record<string, ToolDefinition> = {
  ...builtinTools,                    // 内置基础工具
  ...createGrepTools(ctx),           // Grep 搜索工具
  ...createGlobTools(ctx),           // Glob 文件匹配工具
  ...createAstGrepTools(ctx),        // AST 搜索工具
  ...createSessionManagerTools(ctx), // 会话管理工具
  ...backgroundTools,                // 后台任务工具
  call_omo_agent: callOmoAgent,      // 子代理调用工具
  ...(lookAt ? { look_at: lookAt } : {}),  // 多模态查看工具
  task: delegateTask,                // 任务委托工具
  skill_mcp: skillMcpTool,           // Skill MCP 工具
  skill: skillTool,                  // Skill 执行工具
  interactive_bash,                   // 交互式 Bash 工具
  ...taskToolsRecord,                // Task 系统工具（条件启用）
  ...hashlineToolsRecord,            // Hashline 编辑工具（条件启用）
}
```

注册完成后，会进行参数模式规范化和工具过滤：

```typescript
// src/plugin/tool-registry.ts:153-157
for (const toolDefinition of Object.values(allTools)) {
  normalizeToolArgSchemas(toolDefinition)
}

const filteredTools: ToolsRecord = filterDisabledTools(allTools, pluginConfig.disabled_tools)
```

### 2. 执行 (before → execute → after)

工具执行遵循严格的三段式模型：

**Before 阶段**：在工具实际执行前，运行前置钩子链进行参数处理和上下文注入。

```typescript
// src/plugin/tool-execute-before.ts:54-66
await hooks.writeExistingFileGuard?.["tool.execute.before"]?.(input, output)
await hooks.questionLabelTruncator?.["tool.execute.before"]?.(input, output)
await hooks.claudeCodeHooks?.["tool.execute.before"]?.(input, output)
await hooks.nonInteractiveEnv?.["tool.execute.before"]?.(input, output)
await hooks.commentChecker?.["tool.execute.before"]?.(input, output)
await hooks.directoryAgentsInjector?.["tool.execute.before"]?.(input, output)
await hooks.directoryReadmeInjector?.["tool.execute.before"]?.(input, output)
await hooks.rulesInjector?.["tool.execute.before"]?.(input, output)
// ... 更多钩子
```

**Execute 阶段**：OpenCode 运行时调用实际工具实现，执行具体的业务逻辑。

**After 阶段**：工具执行完成后，运行后置钩子链处理输出和清理工作。

```typescript
// src/plugin/tool-execute-after.ts:109-130
await hooks.toolOutputTruncator?.["tool.execute.after"]?.(input, output)
await hooks.claudeCodeHooks?.["tool.execute.after"]?.(input, output)
await hooks.preemptiveCompaction?.["tool.execute.after"]?.(input, output)
await hooks.contextWindowMonitor?.["tool.execute.after"]?.(input, output)
await hooks.commentChecker?.["tool.execute.after"]?.(input, output)
// ... 更多钩子
```

### 3. 清理

清理阶段负责资源回收和状态管理：

```typescript
// src/plugin/tool-execute-after.ts:45-53
const stored = consumeToolMetadata(input.sessionID, input.callID)
if (stored) {
  if (stored.title) {
    output.title = stored.title
  }
  if (stored.metadata) {
    output.metadata = { ...output.metadata, ...stored.metadata }
  }
}
```

## 工具生命周期流程

完整的工具生命周期流程如下：

1. **初始化阶段**：插件启动时，`createToolRegistry` 收集所有工具定义，进行参数规范化，并根据配置过滤禁用工具。

2. **调用阶段**：当 OpenCode 需要执行工具时，首先触发 `tool.execute.before` 钩子链，允许各个钩子修改输入参数或注入上下文。

3. **执行阶段**：经过 Before 钩子处理后，OpenCode 调用实际工具实现，执行具体的业务逻辑。

4. **后置处理阶段**：工具执行完成后，触发 `tool.execute.after` 钩子链，处理输出截断、错误恢复、元数据存储等任务。

5. **清理阶段**：消费并清理工具执行过程中存储的元数据，释放相关资源。

整个流程确保了工具调用的安全性、可观测性和可扩展性。

## 依赖关系

工具生命周期模块依赖以下核心组件：

**向上依赖（Layer 2）**：
- Tool Registry：提供工具注册和查询能力
- Hook System：提供 before/after 钩子注册和执行机制
- Plugin Interface：与 OpenCode 运行时交互

**向下依赖（Layer 4）**：
- 具体工具实现：如 grep、glob、ast_grep 等工具工厂函数
- MCP 管理器：提供 Skill MCP 工具能力
- 后台任务管理器：支持后台工具执行

**同级依赖（Layer 3）**：
- Hook Execution Order：定义钩子执行顺序
- Tool Guard Hooks：提供安全守卫功能

## 实战示例

### 示例 1: 工具注册与过滤

假设我们需要在配置中禁用某些工具，工具生命周期会如何处理：

```typescript
// 配置示例：.opencode/oh-my-opencode.jsonc
{
  "disabled_tools": ["interactive_bash", "look_at"]
}

// 注册流程：
// 1. createToolRegistry 收集所有工具（包括 interactive_bash 和 look_at）
// 2. 调用 filterDisabledTools(allTools, ["interactive_bash", "look_at"])
// 3. 返回的 filteredTools 中不包含被禁用的工具
// 4. OpenCode 只能使用过滤后的工具
```

这个机制允许用户根据安全策略或项目需求，精确控制可用工具集。

### 示例 2: 工具执行钩子链

当执行 `write` 工具时，完整的生命周期流程如下：

```typescript
// Before 阶段：
// 1. writeExistingFileGuard 检查目标文件是否已存在
//    - 如果存在且未设置覆盖标志，抛出错误或警告
// 2. rulesInjector 注入当前目录的 .sisyphus/rules 规则
// 3. commentChecker 检查是否包含 AI 生成的低质量注释

// Execute 阶段：
// OpenCode 调用实际的文件写入操作

// After 阶段：
// 1. toolOutputTruncator 截断过长的输出内容
// 2. editErrorRecovery 检查编辑错误并尝试恢复
// 3. contextWindowMonitor 监控上下文窗口使用情况
// 4. consumeToolMetadata 消费并清理元数据
```

这个流程确保了文件写入操作的安全性、合规性和可观测性。
