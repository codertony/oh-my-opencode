## 核心职责

文件操作工具是OhMyOpenCode插件的基础能力层，负责提供安全、高效、精确的文件系统交互接口。其核心职责包括：

**文件发现与定位**：通过glob模式匹配和grep内容搜索，帮助Agent快速定位目标文件。glob支持`**/*.ts`等通配符模式，而grep则提供基于正则表达式的内容搜索，两者结合可实现从模糊到精确的文件定位。

**内容读取与解析**：read_file工具为Agent提供文件内容读取能力，支持按行号范围读取、自动检测文件类型，并在读取时为每行附加内容哈希标签（LINE#ID格式），为后续的精确编辑奠定基础。

**安全编辑与写入**：hashline_edit工具采用哈希锚定编辑机制，每个编辑操作都必须引用读取时获得的LINE#ID标签。系统在应用编辑前会验证内容哈希，如果文件自读取后已被修改（哈希不匹配），编辑将被拒绝，从而彻底避免脏写和冲突。

**批量操作支持**：所有工具都内置了安全限制（如60秒超时、100文件限制、256KB输出限制），防止资源耗尽，确保系统稳定性。

## 5 个文件操作工具

### 1. read_file

**功能说明**：read_file是文件读取的基础工具，负责将文件内容加载到Agent上下文中。该工具不仅返回原始文件内容，还会为每一行生成唯一的内容哈希标识（LINE#ID），格式为`行号#哈希|内容`。

**核心机制**：
- 使用Bun.file API进行高效的文件读取
- 通过xxHash32算法计算每行内容的哈希值
- 哈希字典使用16个CID字符（ZPMQVRWSNKTXJBYH）生成2字符哈希ID
- 支持流式读取大文件，避免内存溢出

**代码引用**（src/tools/hashline-edit/hash-computation.ts:22-25）：
```typescript
export function formatHashLine(lineNumber: number, content: string): string {
  const hash = computeLineHash(lineNumber, content)
  return `${lineNumber}#${hash}|${content}`
}
```

**使用场景**：
- 首次访问文件时必须使用read_file获取LINE#ID标签
- 需要查看文件特定行范围的内容
- 编辑文件前必须先读取以获取有效的哈希锚点

### 2. glob

**功能说明**：glob工具提供基于模式匹配的文件发现能力，支持`**/*.ts`、`src/**/*.tsx`等标准glob语法。该工具底层使用ripgrep（rg）实现，具有极高的搜索性能。

**核心机制**：
- 支持60秒超时和100文件数量限制
- 自动按修改时间排序返回结果
- 跨平台支持：优先使用ripgrep，回退到find（Linux/Mac）或PowerShell（Windows）
- 使用信号量（semaphore）控制并发，防止资源竞争

**代码引用**（src/tools/glob/tools.ts:26-45）：
```typescript
execute: async (args, context) => {
  try {
    const cli = await resolveGrepCliWithAutoInstall()
    const runtimeCtx = context as Record<string, unknown>
    const dir = typeof runtimeCtx.directory === "string" ? runtimeCtx.directory : ctx.directory
    const searchPath = args.path ? resolve(dir, args.path) : dir

    const result = await runRgFiles(
      { pattern: args.pattern, paths: [searchPath] },
      cli
    )
    return formatGlobResult(result)
  } catch (e) {
    return `Error: ${e instanceof Error ? e.message : String(e)}`
  }
}
```

**使用场景**：
- 查找特定类型的所有文件（如所有测试文件`**/*.test.ts`）
- 在特定目录下搜索文件（如`src/components/**/*.tsx`）
- 作为grep搜索的前置步骤，先定位文件再搜索内容

### 3. grep

**功能说明**：grep工具提供强大的内容搜索能力，支持完整的正则表达式语法。可以搜索代码中的特定模式，如函数定义、变量使用、错误处理模式等。

**核心机制**：
- 三种输出模式：content（显示匹配行）、files_with_matches（仅显示文件路径）、count（显示匹配计数）
- 支持上下文行（-C参数）显示匹配行周围的内容
- 支持文件类型过滤（include参数）
- 256KB输出限制和60秒超时保护

**代码引用**（src/tools/grep/tools.ts:36-69）：
```typescript
execute: async (args, context) => {
  try {
    const globs = args.include ? [args.include] : undefined
    const runtimeCtx = context as Record<string, unknown>
    const dir = typeof runtimeCtx.directory === "string" ? runtimeCtx.directory : ctx.directory
    const searchPath = args.path ? resolve(dir, args.path) : dir
    const paths = [searchPath]
    const outputMode = args.output_mode ?? "files_with_matches"
    const headLimit = args.head_limit ?? 0

    if (outputMode === "count") {
      const results = await runRgCount({ pattern: args.pattern, paths, globs })
      return formatCountResult(results)
    }

    const result = await runRg({ pattern: args.pattern, paths, globs, context: 0, outputMode, headLimit })
    return formatGrepResult(result)
  } catch (e) {
    return `Error: ${e instanceof Error ? e.message : String(e)}`
  }
}
```

**使用场景**：
- 查找所有使用特定函数的位置
- 搜索TODO、FIXME等标记
- 查找特定错误处理模式或正则表达式匹配

### 4. edit_file (hashline_edit)

**功能说明**：hashline_edit是OhMyOpenCode的核心编辑工具，采用哈希锚定机制确保编辑的精确性和安全性。每个编辑操作都必须引用读取时获得的LINE#ID标签，系统在应用编辑前会验证内容哈希。

**核心机制**：
- 三种编辑操作：replace（替换）、append（追加）、prepend（前置）
- 哈希验证：应用编辑前验证LINE#ID对应的内容哈希是否匹配
- 自底向上应用：多个编辑按行号降序应用，避免行号偏移问题
- 自动格式化：编辑完成后自动触发代码格式化

**代码引用**（src/tools/hashline-edit/hashline-edit-executor.ts:102-132）：
```typescript
const edits = deleteMode ? [] : normalizeHashlineEdits(args.edits)
const file = Bun.file(filePath)
const exists = await file.exists()
if (!exists && !deleteMode && !canCreateFromMissingFile(edits)) {
  return `Error: File not found: ${filePath}`
}

const rawOldContent = exists ? Buffer.from(await file.arrayBuffer()).toString("utf8") : ""
const oldEnvelope = canonicalizeFileText(rawOldContent)

const applyResult = applyHashlineEditsWithReport(oldEnvelope.content, edits)
const canonicalNewContent = applyResult.content

const writeContent = restoreFileText(canonicalNewContent, oldEnvelope)
await Bun.write(filePath, writeContent)
```

**使用场景**：
- 精确修改代码中的特定行或行范围
- 在函数前后插入新代码
- 删除不再需要的代码块
- 重命名文件或删除文件

### 5. write_file

**功能说明**：write_file提供文件写入能力，用于创建新文件或覆盖现有文件。与edit_file不同，write_file不依赖LINE#ID标签，直接写入完整内容。

**核心机制**：
- 使用Bun.write API进行高效的文件写入
- 支持创建新文件和覆盖现有文件
- 自动处理目录创建（如果父目录不存在）
- 与hashline_edit共享底层的文件文本规范化逻辑

**使用场景**：
- 创建全新的源文件
- 生成配置文件或模板文件
- 导出数据到JSON、CSV等格式
- 覆盖现有文件的全部内容（谨慎使用）

## 文件操作流程

文件操作遵循严格的读取-编辑-验证流程，确保每次编辑都是安全、可预测的：

```
┌─────────────────────────────────────────────────────────────────┐
│                     文件操作流程                                 │
└─────────────────────────────────────────────────────────────────┘

Phase 1: 发现 (Discovery)
    │
    ├─► glob(pattern="**/*.ts") ──► 获取文件列表
    │
    └─► grep(pattern="function.*main") ──► 定位目标文件

Phase 2: 读取 (Read)
    │
    └─► read_file(path) ──► 返回带LINE#ID的内容
        │
        └─► 10#VK| function hello() {
            11#XJ|   return "world";
            12#MB| }

Phase 3: 编辑规划 (Plan)
    │
    └─► 确定编辑操作：replace/append/prepend
        确定锚点：pos="11#XJ", end="11#XJ"
        准备新内容：lines=["  return 'hello';"]

Phase 4: 执行 (Execute)
    │
    └─► hashline_edit(filePath, edits)
        │
        ├─► 验证LINE#ID哈希是否匹配
        ├─► 按行号降序排序编辑
        ├─► 应用每个编辑操作
        ├─► 生成diff报告
        └─► 写入文件

Phase 5: 验证 (Verify)
    │
    └─► 返回编辑结果和diff
        成功："Updated /path/to/file.ts"
        失败："Error: hash mismatch..."
```

```typescript
export function formatHashLine(lineNumber: number, content: string): string {

export function formatHashLines(content: string): string {
  if (!content) return ""
  const lines = content.split("\n")
  return lines.map((line, index) => formatHashLine(index + 1, line)).join("\n")
}
```

```typescript
// src/tools/hashline-edit/hashline-edit-executor.ts:85-130
export async function executeHashlineEditTool(
  args: HashlineEditArgs, 
  context: ToolContext, 
  pluginCtx?: PluginContext
): Promise<string> {
  const filePath = args.filePath
  const { delete: deleteMode, rename } = args

  if (deleteMode && args.edits.length > 0) {
    return "Error: delete mode requires edits to be an empty array"
  }

  const edits = deleteMode ? [] : normalizeHashlineEdits(args.edits)
  const file = Bun.file(filePath)
  const exists = await file.exists()
  
  const rawOldContent = exists 
    ? Buffer.from(await file.arrayBuffer()).toString("utf8") 
    : ""
  const oldEnvelope = canonicalizeFileText(rawOldContent)

  const applyResult = applyHashlineEditsWithReport(oldEnvelope.content, edits)
  const writeContent = restoreFileText(applyResult.content, oldEnvelope)
  await Bun.write(filePath, writeContent)
  
  return `Updated ${filePath}`
}
```

## 依赖关系

文件操作工具与系统其他组件存在以下依赖关系：

**向上依赖**：
- ToolRegistry：所有文件操作工具通过ToolRegistry注册和暴露
- PluginInterface：通过OpenCode插件接口接收调用请求
- PermissionLayer：文件操作受权限层保护，防止越权访问

**横向依赖**：
- Shared模块：共享的信号量（semaphore）控制并发访问
- Hooks系统：文件操作前后可触发各种钩子（如writeExistingFileGuard）
- LSP客户端：编辑完成后自动触发代码格式化

**向下依赖**：
- Bun API：使用Bun.file和Bun.write进行高效的文件IO
- ripgrep：glob和grep工具底层依赖rg命令行工具
- diff库：生成编辑前后的统一diff格式
