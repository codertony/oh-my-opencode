工具注册系统位于插件架构的第三层（工具层），负责将 26 个独立工具组装成统一的工具注册表，并根据用户配置进行条件过滤。

---

## 核心职责

工具注册系统是 oh-my-opencode 插件的核心组件之一，承担以下关键职责：

**工具组装**：通过 `createToolRegistry()` 函数，将分散在 15 个目录中的 26 个工具统一组装成 `ToolsRecord` 对象。这个过程涉及两种创建模式：工厂函数模式（19 个工具）和直接定义模式（7 个工具）。

**条件过滤**：根据 `disabled_tools` 配置项，动态过滤掉用户禁用的工具。这是实现"按需启用"的关键机制，让用户可以精确控制哪些工具对 AI 可见。

**参数规范化**：对所有工具的参数模式进行统一规范化处理，确保工具定义符合 OpenCode 插件接口要求。

**预算控制**：当配置 `max_tools` 时，自动裁剪低优先级工具，确保工具数量在模型上下文预算范围内。

### 1. LSP Refactoring (6 个工具)

| 工具名 | 用途 | 参数 |
|--------|------|------|
| `lsp_goto_definition` | 跳转到符号定义 | filePath, line, character |
| `lsp_find_references` | 查找符号所有引用 | filePath, line, character, includeDeclaration |
| `lsp_symbols` | 文档大纲或工作区符号搜索 | filePath, scope, query, limit |
| `lsp_diagnostics` | 获取语言服务器的错误/警告 | filePath, severity |
| `lsp_prepare_rename` | 重命名前验证 | filePath, line, character |
| `lsp_rename` | 跨工作区安全重命名 | filePath, line, character, newName |

| 工具名 | 用途 | 特点 |
|--------|------|------|
| `grep` | 正则内容搜索 | 60秒超时，256KB输出限制 |
| `glob` | 文件模式匹配 | 60秒超时，100文件限制 |
| `ast_grep_search` | AST感知代码搜索 | 支持25种语言，元变量匹配 |
| `ast_grep_replace` | AST感知代码替换 | 预览模式，安全重写 |

### 3. Session Management (4 个工具)

| 工具名 | 用途 |
|--------|------|
| `session_list` | 列出所有会话 |
| `session_read` | 读取会话消息历史 |
| `session_search` | 在会话中搜索内容 |
| `session_info` | 获取会话元数据 |

### 4. Task Management (4 个工具)

| 工具名 | 用途 |
|--------|------|
| `task_create` | 创建新任务 |
| `task_list` | 列出所有任务 |
| `task_get` | 获取任务详情 |

### 5. Delegation (1 个工具)

| 工具名 | 用途 |
|--------|------|

## 工具注册流程

`createToolRegistry()` 的组装过程遵循以下步骤：

```typescript
// 步骤1: 创建动态工具
const backgroundTools = createBackgroundTools(manager, client);
const callOmoAgent = createCallOmoAgent(ctx, manager, ...);
const delegateTask = createDelegateTask({ ... });

// 步骤2: 条件创建可选工具
const lookAt = isMultimodalLookerEnabled ? createLookAt(ctx) : null;

// 步骤3: 创建技能相关工具
const skillMcpTool = createSkillMcpTool({ ... });
const skillTool = createSkillTool({ ... });

// 步骤4: 根据实验性功能标志创建工具
const taskToolsRecord = taskSystemEnabled ? { task_create, task_get, task_list, task_update } : {};
const hashlineToolsRecord = hashlineEnabled ? { edit: createHashlineEditTool(ctx) } : {};

// 步骤5: 合并所有工具
const allTools = {
  ...builtinTools,           // 6个LSP工具
  ...createGrepTools(ctx),   // grep + glob
  ...createAstGrepTools(ctx),// ast_grep_search + ast_grep_replace
  ...createSessionManagerTools(ctx), // 4个会话工具
  ...backgroundTools,        // background_output + background_cancel
  call_omo_agent: callOmoAgent,
  ...(lookAt ? { look_at: lookAt } : {}),
  task: delegateTask,
  skill_mcp: skillMcpTool,
  skill: skillTool,
  interactive_bash,
  ...taskToolsRecord,
  ...hashlineToolsRecord,
};

// 步骤6: 参数规范化
for (const toolDefinition of Object.values(allTools)) {
  normalizeToolArgSchemas(toolDefinition);
}

// 步骤7: 条件过滤
const filteredTools = filterDisabledTools(allTools, pluginConfig.disabled_tools);
```

## 条件组装机制

`disabled_tools` 配置通过 `filterDisabledTools()` 函数实现工具过滤：

```typescript
// src/shared/disabled-tools.ts
export function filterDisabledTools(
  tools: Record<string, ToolDefinition>,
  disabledTools: readonly string[] | undefined
): Record<string, ToolDefinition> {
  if (!disabledTools || disabledTools.length === 0) {
    return tools;  // 无禁用配置，返回全部
  }

  const disabledToolSet = new Set(disabledTools);
  const filtered: Record<string, ToolDefinition> = {};
  
  for (const [toolName, toolDefinition] of Object.entries(tools)) {
    if (!disabledToolSet.has(toolName)) {
      filtered[toolName] = toolDefinition;  // 只保留未禁用的
    }
  }
  return filtered;
}
```

配置示例（`~/.config/opencode/oh-my-opencode.jsonc`）：

```jsonc
{
  "disabled_tools": [
    "interactive_bash",  // 禁用Tmux交互
    "look_at",           // 禁用图像分析
    "session_search"     // 禁用会话搜索
  ]
}
```

## 实战示例

### 场景：禁用特定工具以优化上下文

假设你正在处理一个纯后端项目，不需要前端相关的视觉分析工具，可以通过配置禁用 `look_at` 和 `interactive_bash`：

```jsonc
// ~/.config/opencode/oh-my-opencode.jsonc
{
  "disabled_tools": [
    "look_at",           // 不需要图像分析
    "interactive_bash",  // 不需要Tmux交互
    "session_search"     // 不需要搜索历史会话
  ],
  "disabled_agents": [
    "multimodal-looker"  // 同时禁用多模态代理
  ]
}
```

配置生效后，`createToolRegistry()` 会：

1. 检测到 `multimodal-looker` 在 `disabled_agents` 中
2. `isMultimodalLookerEnabled` 设为 `false`
3. `lookAt` 变量为 `null`，不会加入 `allTools`
4. `filterDisabledTools()` 从最终工具集中移除 `look_at`、`interactive_bash` 和 `session_search`

结果：AI 代理看不到这些工具，上下文更精简，token 消耗更低。
