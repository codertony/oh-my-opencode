## 核心职责

代码智能工具为 AI 代理提供 IDE 级别的代码分析能力，使代理能够像专业开发者一样理解和操作代码。这些工具的核心职责包括：

1. **符号导航**：通过 LSP 协议实现跳转到定义、查找引用等功能，帮助代理理解代码间的依赖关系
2. **代码诊断**：在构建前捕获类型错误和潜在问题，提供与 IDE 相同的实时反馈
3. **重构支持**：安全的重命名操作，自动处理跨文件的符号更新
4. **AST 模式匹配**：基于抽象语法树的智能搜索和替换，支持 25 种编程语言
5. **代码理解**：提取文件结构、类层次、函数签名等元信息

这些工具让代理不再依赖简单的文本搜索，而是能够真正理解代码的语义结构。

## LSP 工具

LSP（Language Server Protocol）工具通过标准化的协议与语言服务器通信，提供 IDE 级别的代码分析能力。oh-my-opencode 实现了完整的 LSP 客户端栈，不依赖 OpenCode 内置的 LSP 功能。

### 1. lsp_goto_definition

跳转到符号定义位置，帮助理解代码中某个标识符是在哪里被定义的。

**参数**：
- `filePath`: 文件路径
- `line`: 行号（1-based）
- `character`: 列号（0-based）

**实现要点**（`src/tools/lsp/goto-definition-tool.ts` 第 14-22 行）：

```typescript
const result = await withLspClient(args.filePath, async (client) => {
  return (await client.definition(args.filePath, args.line, args.character)) as
    | Location
    | Location[]
    | LocationLink[]
    | null
})
```

**使用场景**：
- 查看函数/类的定义位置
- 追踪类型定义来源
- 理解模块导出关系

### 2. lsp_find_references

查找符号在整个工作区中的所有引用位置。

**参数**：
- `filePath`: 文件路径
- `line`: 行号（1-based）
- `character`: 列号（0-based）
- `includeDeclaration`: 是否包含声明本身（可选，默认 true）

**实现要点**（`src/tools/lsp/find-references-tool.ts` 第 18-22 行）：

```typescript
const result = await withLspClient(args.filePath, async (client) => {
  return (await client.references(args.filePath, args.line, args.character, args.includeDeclaration ?? true)) as
    | Location[]
    | null
})
```

**特性**：
- 自动截断大量结果（默认最多 100 条）
- 返回格式化的位置信息
- 支持跨文件引用查找

### 3. lsp_diagnostics

在构建前获取代码的错误、警告和提示信息。

**参数**：
- `filePath`: 文件或目录路径
- `severity`: 严重级别过滤（error/warning/information/hint/all）
- `extension`: 目录检查时的文件扩展名（如 `.ts`）

**实现要点**（`src/tools/lsp/diagnostics-tool.ts` 第 45-54 行）：


### 4. lsp_symbols

获取文件的符号大纲或在工作区中搜索符号。

**参数**：
- `filePath`: 文件路径（用于确定 LSP 上下文）
- `scope`: 搜索范围（document/workspace）
- `query`: 符号名称（workspace 模式必需）
- `limit`: 最大结果数（默认 50）

**实现要点**（`src/tools/lsp/symbols-tool.ts` 第 24-46 行）：


**两种模式**：

## AST-grep 工具

AST-grep 是基于抽象语法树的代码搜索和替换工具，支持 25 种编程语言。与文本搜索不同，AST-grep 理解代码结构，能够进行语义级别的匹配。

### 1. ast_grep_search

使用 AST 模式匹配搜索代码。

**参数**：
- `pattern`: AST 模式（支持元变量 `$VAR` 和 `$$$`）
- `lang`: 目标语言（25 种支持）
- `paths`: 搜索路径（默认当前目录）
- `globs`: 包含/排除模式（以 `!` 开头表示排除）
- `context`: 匹配上下文行数

**实现要点**（`src/tools/ast-grep/tools.ts` 第 38-80 行）：

```typescript
export const ast_grep_search: ToolDefinition = tool({
  description:
    "Search code patterns across filesystem using AST-aware matching. Supports 25 languages. " +
    "Use meta-variables: $VAR (single node), $$$ (multiple nodes). " +
    "IMPORTANT: Patterns must be complete AST nodes (valid code).",
  args: {
    pattern: tool.schema.string().describe("AST pattern with meta-variables ($VAR, $$$). Must be complete AST node."),
    lang: tool.schema.enum(CLI_LANGUAGES).describe("Target language"),
    // ...
  },
  execute: async (args, context) => {
    const result = await runSg({
      pattern: args.pattern,
      lang: args.lang as CliLanguage,
      paths: args.paths ?? [ctx.directory],
      // ...
    })
    return formatSearchResult(result)
  },
})
```

**模式示例**：
- `console.log($MSG)` - 匹配所有 console.log 调用
- `def $FUNC($$$):` - 匹配所有函数定义
- `async function $NAME($$$) { $$$ }` - 匹配异步函数

### 2. ast_grep_replace

AST 感知的代码替换，支持预览模式。

**参数**：
- `pattern`: 要匹配的 AST 模式
- `rewrite`: 替换模式（可使用 `$VAR` 引用匹配内容）
- `lang`: 目标语言
- `paths`: 搜索路径
- `globs`: 包含/排除模式
- `dryRun`: 预览模式（默认 true）

**实现要点**（`src/tools/ast-grep/tools.ts` 第 82-114 行）：

```typescript
export const ast_grep_replace: ToolDefinition = tool({
  description:
    "Replace code patterns across filesystem with AST-aware rewriting. " +
    "Dry-run by default. Use meta-variables in rewrite to preserve matched content.",
  args: {
    pattern: tool.schema.string().describe("AST pattern to match"),
    rewrite: tool.schema.string().describe("Replacement pattern (can use $VAR from pattern)"),
    dryRun: tool.schema.boolean().optional().describe("Preview changes without applying (default: true)"),
    // ...
  },
  execute: async (args, context) => {
    const result = await runSg({
      pattern: args.pattern,
      rewrite: args.rewrite,
      updateAll: args.dryRun === false,
      // ...
    })
    return formatReplaceResult(result, args.dryRun !== false)
  },
})
```

**替换示例**：
```
pattern: 'console.log($MSG)'
rewrite: 'logger.info($MSG)'
```

## 代码智能流程

代码智能工具的执行遵循以下流程：

1. **工具调用**：代理通过工具注册表调用 LSP 或 AST-grep 工具
2. **客户端获取**：`withLspClient` 或 `runSg` 获取/创建对应的客户端
3. **文件打开**：LSP 工具需要先将文件通过 `didOpen` 通知发送给语言服务器
4. **请求执行**：发送具体的 LSP 请求（如 definition/references）或执行 ast-grep CLI
5. **结果格式化**：将原始结果转换为人类可读的格式
6. **返回代理**：格式化后的结果返回给调用代理

### 片段 1: LSP 客户端包装器

`src/tools/lsp/lsp-client-wrapper.ts` 第 78-115 行：

```typescript
export async function withLspClient<T>(filePath: string, fn: (client: LSPClient) => Promise<T>): Promise<T> {
  const absPath = resolve(filePath)

  if (isDirectoryPath(absPath)) {
    throw new Error(
      `Directory paths are not supported by this LSP tool. ` +
        `Use lsp_diagnostics with the 'extension' parameter for directory diagnostics.`
    )
  }

  const ext = extname(absPath)
  const result = findServerForExtension(ext)

  if (result.status !== "found") {
    throw new Error(formatServerLookupError(result))
  }

  const server = result.server
  const root = findWorkspaceRoot(absPath)
  const client = await lspManager.getClient(root, server)

  try {
    return await fn(client)
  } finally {
    lspManager.releaseClient(root, server.id)
  }
}
```

```typescript
export async function runSg(options: RunOptions): Promise<SgResult> {
  const shouldSeparateWritePass = !!(options.rewrite && options.updateAll)

  const args = ["run", "-p", options.pattern, "--lang", options.lang, "--json=compact"]

  if (options.rewrite) {
    args.push("-r", options.rewrite)
    if (options.updateAll && !shouldSeparateWritePass) {
      args.push("--update-all")
    }
  }

  if (options.context && options.context > 0) {
    args.push("-C", String(options.context))
  }

  const paths = options.paths && options.paths.length > 0 ? options.paths : ["."]
  args.push(...paths)

  // ... spawn process and collect output
}
```

```typescript
async openFile(filePath: string): Promise<void> {
  const absPath = resolve(filePath)
  const uri = pathToFileURL(absPath).href
  const text = readFileSync(absPath, "utf-8")

  if (!this.openedFiles.has(absPath)) {
    const ext = extname(absPath)
    const languageId = getLanguageId(ext)
    const version = 1

    this.sendNotification("textDocument/didOpen", {
      textDocument: {
        uri,
        languageId,
        version,
        text,
      },
    })

    this.openedFiles.add(absPath)
    this.documentVersions.set(uri, version)
    this.lastSyncedText.set(uri, text)
    await new Promise((r) => setTimeout(r, 1000))  // 等待服务器初始化
    return
  }
  // ... 处理已打开文件的变更同步
}
```

1. **LSP 工具依赖**：
   - `lsp-client.ts`: LSP 协议客户端实现
