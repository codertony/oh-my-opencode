模式匹配工具位于共享工具层（Layer 3），为上层工具系统提供统一的文件搜索和内容匹配能力。该模块封装了 Glob 模式匹配和正则表达式匹配两种核心机制，通过统一的接口暴露给工具层使用。

---

## 核心职责

模式匹配工具模块承担着以下核心职责：

**文件定位与筛选**：通过 Glob 模式（如 `**/*.ts`、`src/**/*.test.ts`）快速定位项目中的文件。Glob 工具支持通配符匹配，能够递归搜索目录树，并按修改时间排序返回结果。这对于大型代码库中的文件发现至关重要。

**内容搜索与匹配**：通过正则表达式在文件内容中进行模式匹配，支持复杂的搜索需求。Regex 工具提供三种输出模式：内容模式显示匹配行、文件模式仅返回文件路径、计数模式显示每个文件的匹配次数。

**模式编译与缓存**：`pattern-matcher` 模块提供模式编译功能，将 Glob 风格的通配符模式转换为正则表达式，并通过缓存机制避免重复编译。这对于需要频繁匹配的场景（如钩子系统）性能优化明显。

**安全限制与资源管理**：所有匹配操作都内置安全限制，包括 60 秒超时、输出大小限制（Glob 为 10MB，Grep 为 256KB）、并发控制（通过信号量限制 ripgrep 线程数）。这些限制防止了资源耗尽和长时间阻塞。

**跨平台兼容**：底层 CLI 层自动检测并使用可用的搜索后端（ripgrep、grep、PowerShell），确保在不同操作系统（Linux、macOS、Windows）上都能正常工作。

## 模式匹配工具函数

### 1. Glob 模式

Glob 模式用于文件路径匹配，支持以下通配符：

- `*` - 匹配任意字符（不包括路径分隔符）
- `**` - 递归匹配任意层级目录
- `?` - 匹配单个字符
- `{a,b}` - 匹配 a 或 b

**核心实现**（`src/tools/glob/cli.ts` 第 22-36 行）：

```typescript
function buildRgArgs(options: GlobOptions): string[] {
  const args: string[] = [
    ...RG_FILES_FLAGS,
    `--threads=${Math.min(options.threads ?? DEFAULT_RG_THREADS, DEFAULT_RG_THREADS)}`,
    `--max-depth=${Math.min(options.maxDepth ?? DEFAULT_MAX_DEPTH, DEFAULT_MAX_DEPTH)}`,
  ]

  if (options.hidden !== false) args.push("--hidden")
  if (options.follow !== false) args.push("--follow")
  if (options.noIgnore) args.push("--no-ignore")

  args.push(`--glob=${options.pattern}`)

  return args
}
```

Glob 工具通过 ripgrep 的 `--files` 和 `--glob` 参数实现高效的文件发现。结果按修改时间降序排列，便于获取最新变更的文件。

### 2. Regex 模式

Regex 模式用于文件内容搜索，支持完整的正则表达式语法：

**核心实现**（`src/tools/grep/cli.ts` 第 18-64 行）：

```typescript
function buildRgArgs(options: GrepOptions): string[] {
  const args: string[] = [
    ...RG_SAFETY_FLAGS,
    `--threads=${Math.min(options.threads ?? DEFAULT_RG_THREADS, DEFAULT_RG_THREADS)}`,
    `--max-depth=${Math.min(options.maxDepth ?? DEFAULT_MAX_DEPTH, DEFAULT_MAX_DEPTH)}`,
    `--max-filesize=${options.maxFilesize ?? DEFAULT_MAX_FILESIZE}`,
    `--max-count=${Math.min(options.maxCount ?? DEFAULT_MAX_COUNT, DEFAULT_MAX_COUNT)}`,
    `--max-columns=${Math.min(options.maxColumns ?? DEFAULT_MAX_COLUMNS, DEFAULT_MAX_COLUMNS)}`,
  ]

  if (options.caseSensitive) args.push("--case-sensitive")
  if (options.wholeWord) args.push("-w")
  if (options.fixedStrings) args.push("-F")
  if (options.multiline) args.push("-U")

  if (options.globs) {
    for (const glob of options.globs) {
      args.push(`--glob=${glob}`)
    }
  }

  return args
}
```

Grep 工具支持多种匹配模式：大小写敏感/不敏感、全词匹配、固定字符串匹配、多行匹配等。通过 `--glob` 参数可以限制搜索的文件类型。

### 3. 模式编译

`pattern-matcher` 模块提供将 Glob 风格模式编译为正则表达式的功能：

**核心实现**（`src/shared/pattern-matcher.ts` 第 7-32 行）：

```typescript
const regexCache = new Map<string, RegExp>()

export function matchesToolMatcher(toolName: string, matcher: string): boolean {
  if (!matcher) {
    return true
  }
  const patterns = matcher.split("|").map((p) => p.trim())
  return patterns.some((p) => {
    if (p.includes("*")) {
      let regex = regexCache.get(p)
      if (!regex) {
        const escaped = escapeRegexExceptAsterisk(p)
        regex = new RegExp(`^${escaped.replace(/\*/g, ".*")}$`, "i")
        regexCache.set(p, regex)
      }
      return regex.test(toolName)
    }
    return p.toLowerCase() === toolName.toLowerCase()
  })
}
```

模式编译使用缓存机制（`regexCache`）避免重复编译相同的模式。支持管道符（`|`）分隔的多个模式，实现"或"逻辑匹配。

### 4. 模式匹配

模式匹配是连接配置与执行的关键环节。`findMatchingHooks` 函数根据工具名称查找匹配的钩子配置：

**核心实现**（`src/shared/pattern-matcher.ts` 第 34-46 行）：

```typescript
export function findMatchingHooks(
  config: ClaudeHooksConfig,
  eventName: keyof ClaudeHooksConfig,
  toolName?: string
): HookMatcher[] {
  const hookMatchers = config[eventName]
  if (!hookMatchers) return []

  return hookMatchers.filter((hookMatcher) => {
    if (!toolName) return true
    return matchesToolMatcher(toolName, hookMatcher.matcher)
  })
}
```

该函数遍历配置中的钩子匹配器，使用 `matchesToolMatcher` 检查每个匹配器是否与当前工具名称匹配。这是 Claude Code 钩子系统的核心匹配逻辑。

## 模式匹配流程

模式匹配的使用流程遵循以下步骤：

1. **模式定义**：用户在配置或工具调用中定义匹配模式（Glob 或 Regex）
2. **模式编译**：系统将模式编译为内部表示（正则表达式或 CLI 参数）
3. **执行匹配**：调用底层 CLI 工具（ripgrep/grep）执行实际匹配
4. **结果解析**：解析 CLI 输出，转换为结构化数据
5. **结果返回**：将匹配结果返回给调用方

对于频繁使用的模式，编译结果会被缓存以提高性能。所有匹配操作都受信号量控制，防止并发过多导致系统资源耗尽。

export function createGlobTools(ctx: PluginInput): Record<string, ToolDefinition> {
  const glob: ToolDefinition = tool({
    description:
      "Fast file pattern matching tool with safety limits (60s timeout, 100 file limit). " +
      "Supports glob patterns like \"**/*.js\" or \"src/**/*.ts\". " +
      "Returns matching file paths sorted by modification time.",
    args: {
      pattern: tool.schema.string().describe("The glob pattern to match files against"),
      path: tool.schema.string().optional().describe("The directory to search in"),
    },
    execute: async (args, context) => {
      const cli = await resolveGrepCliWithAutoInstall()
      const searchPath = args.path ? resolve(dir, args.path) : dir
      const result = await runRgFiles({ pattern: args.pattern, paths: [searchPath] }, cli)
      return formatGlobResult(result)
    },
  })
  return { glob }
}

## 性能优化建议

1. **使用 Glob 限制文件范围**：在执行 Grep 搜索时，通过 `include` 参数限制文件类型，减少搜索范围
2. **合理使用缓存**：`pattern-matcher` 的缓存机制对重复模式匹配有明显性能提升
3. **设置合理的 head_limit**：当只需要部分结果时，设置 `head_limit` 避免处理大量匹配项
4. **避免过深的递归**：通过 `maxDepth` 参数限制搜索深度，特别是在大型 monorepo 中
