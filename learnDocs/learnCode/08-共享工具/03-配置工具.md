## 核心职责

配置工具模块负责处理 oh-my-opencode 插件的所有配置相关基础操作。其核心职责包括四个方面：

**配置路径解析**：跨平台识别 OpenCode 配置目录，支持 CLI 和桌面版两种运行模式。通过环境变量检测、XDG 规范遵循以及 Tauri 应用标识符解析，确保在不同操作系统（macOS、Windows、Linux）上都能正确定位配置文件。

**JSONC 解析**：提供带注释的 JSON 解析能力，支持尾随逗号。相比标准 JSON.parse，能够处理用户友好的配置文件格式，同时提供详细的语法错误信息。

**配置迁移**：自动将旧版本配置升级到新版本，包括代理名称映射、钩子名称更新、模型版本迁移等。迁移过程会创建备份文件，确保数据安全。

**深度合并**：实现多层配置的递归合并策略，支持对象递归合并、数组替换而非连接、以及禁用列表的集合去重合并。

## 配置工具函数

### 1. 配置路径解析

配置路径解析负责在不同平台和运行模式下定位 OpenCode 配置目录。

**核心机制**：

1. **CLI 模式**：通过 `OPENCODE_CONFIG_DIR` 环境变量或 XDG 规范（`~/.config/opencode`）定位
2. **桌面版模式**：使用 Tauri 应用标识符（`ai.opencode.desktop`）确定配置目录
3. **跨平台支持**：根据操作系统（darwin、win32、linux）使用不同的路径规则
4. **开发版本检测**：通过版本号中的 `-dev` 或 `.dev` 后缀识别开发构建

**代码示例**（来自 `src/shared/opencode-config-dir.ts` 第 66-90 行）：

### 2. JSONC 解析

JSONC（JSON with Comments）解析支持在 JSON 中包含注释和尾随逗号，使配置文件更易读和维护。

**核心机制**：

1. **注释支持**：允许 `//` 单行注释和 `/* */` 多行注释
2. **尾随逗号**：对象和数组最后一个元素后的逗号被允许
3. **错误处理**：提供详细的解析错误信息，包括错误位置和类型
4. **安全解析**：`parseJsoncSafe` 版本在解析失败时返回 null 而非抛出异常

**代码示例**（来自 `src/shared/jsonc-parser.ts` 第 10-25 行）：

```typescript
export function parseJsonc<T = unknown>(content: string): T {
  const errors: ParseError[] = []
  const result = parse(content, errors, {
    allowTrailingComma: true,
    disallowComments: false,
  }) as T

  if (errors.length > 0) {
    const errorMessages = errors
      .map((e) => `${printParseErrorCode(e.error)} at offset ${e.offset}`)
      .join(", ")
    throw new SyntaxError(`JSONC parse error: ${errorMessages}`)
  }

  return result
}
```

### 3. 配置迁移

配置迁移系统自动将旧版本配置升级到新版本，确保向后兼容性。

**核心机制**：

1. **迁移记录**：使用 `_migrations` 字段跟踪已应用的迁移，避免重复执行
2. **代理名称映射**：将旧代理名称（如 `omo_agent`）映射到新名称（`sisyphus_agent`）
3. **模型版本更新**：自动更新过时的模型 ID 到当前推荐版本
4. **钩子名称迁移**：处理已废弃的钩子名称，从禁用列表中移除
5. **备份机制**：迁移前自动创建带时间戳的备份文件

**代码示例**（来自 `src/shared/migration/config-migration.ts` 第 113-143 行）：

```typescript
if (needsWrite) {
  const timestamp = new Date().toISOString().replace(/[:.]/g, "-")
```

### 4. 深度合并

深度合并实现多层配置（用户级 + 项目级）的智能合并策略。

**核心机制**：

1. **对象递归合并**：嵌套对象逐层合并，而非简单替换
2. **数组替换策略**：数组直接替换，不进行连接操作
3. **undefined 保护**：override 中的 undefined 值不会覆盖 base 中的有效值
4. **安全防护**：跳过 `__proto__`、`constructor`、`prototype` 等危险键
5. **深度限制**：最大递归深度 50 层，防止循环引用导致栈溢出

**代码示例**（来自 `src/shared/deep-merge.ts` 第 23-53 行）：

```typescript
export function deepMerge<T extends Record<string, unknown>>(
  base: T | undefined,
  override: T | undefined,
  depth = 0
): T | undefined {
  if (!base && !override) return undefined
  if (!base) return override
  if (!override) return base
  if (depth > MAX_DEPTH) return override ?? base

  const result = { ...base } as Record<string, unknown>

  for (const key of Object.keys(override)) {
    if (DANGEROUS_KEYS.has(key)) continue
    const baseValue = base[key]
    const overrideValue = override[key]
    if (overrideValue === undefined) continue

    if (isPlainObject(baseValue) && isPlainObject(overrideValue)) {
      result[key] = deepMerge(baseValue, overrideValue, depth + 1)
    } else {
      result[key] = overrideValue
    }
  }

  return result as T
}
```

## 配置工具流程

配置工具的使用遵循以下流程：

1. **路径检测**：`getOpenCodeConfigDir` 确定配置目录位置
2. **文件检测**：`detectPluginConfigFile` 查找 `.jsonc` 或 `.json` 配置文件
3. **内容解析**：`parseJsonc` 解析配置文件内容
4. **配置迁移**：`migrateConfigFile` 执行必要的配置升级
5. **多层合并**：`deepMerge` 合并用户级和项目级配置
6. **错误处理**：`addConfigLoadError` 记录加载过程中的错误

### 片段 1：配置路径解析（跨平台支持）

```typescript
// src/shared/opencode-config-dir.ts:25-43
function getTauriConfigDir(identifier: string): string {
  const platform = process.platform

  switch (platform) {
    case "darwin":
      return join(homedir(), "Library", "Application Support", identifier)

    case "win32": {
      const appData = process.env.APPDATA || join(homedir(), "AppData", "Roaming")
      return win32.join(appData, identifier)
    }

    case "linux":
    default: {
      const xdgConfig = process.env.XDG_CONFIG_HOME || join(homedir(), ".config")
      return join(xdgConfig, identifier)
    }
  }
}
```

### 片段 2：JSONC 安全解析

```typescript
// src/shared/jsonc-parser.ts:27-42
export function parseJsoncSafe<T = unknown>(content: string): JsoncParseResult<T> {
  const errors: ParseError[] = []
  const data = parse(content, errors, {
    allowTrailingComma: true,
    disallowComments: false,
  }) as T | null

  return {
    data: errors.length > 0 ? null : data,
    errors: errors.map((e) => ({
      message: printParseErrorCode(e.error),
      offset: e.offset,
      length: e.length,
    })),
  }
}
```

```typescript
// src/plugin-config.ts:112-159
export function mergeConfigs(
  base: OhMyOpenCodeConfig,
  override: OhMyOpenCodeConfig
): OhMyOpenCodeConfig {
  return {
    ...base,
    ...override,
    agents: deepMerge(base.agents, override.agents),
    categories: deepMerge(base.categories, override.categories),
    disabled_agents: [
      ...new Set([
        ...(base.disabled_agents ?? []),
        ...(override.disabled_agents ?? []),
      ]),
    ],
    // ... 其他禁用列表同样使用 Set 去重
    claude_code: deepMerge(base.claude_code, override.claude_code),
  }
}
```

### 示例 1: 配置路径解析

场景：在插件启动时确定用户级和项目级配置路径。

```typescript
import { getOpenCodeConfigDir, detectPluginConfigFile } from "./shared"
import { join } from "path"

// 获取用户级配置目录
const userConfigDir = getOpenCodeConfigDir({ binary: "opencode" })
const userDetected = detectPluginConfigFile(userConfigDir)
const userConfigPath = userDetected.format !== "none" 
  ? userDetected.path 
  : join(userConfigDir, "oh-my-opencode.json")

// 获取项目级配置目录
const projectBasePath = join(process.cwd(), ".opencode")
const projectDetected = detectPluginConfigFile(projectBasePath)

  ? projectDetected.path
  : join(projectBasePath, "oh-my-opencode.json")

console.log("User config:", userConfigPath)
console.log("Project config:", projectConfigPath)
```

### 示例 2: JSONC 解析与迁移

场景：加载配置文件并自动执行必要的迁移。

```typescript
import { parseJsonc, migrateConfigFile } from "./shared"
import * as fs from "fs"

function loadAndMigrateConfig(configPath: string) {
  try {
    // 读取配置文件
    const content = fs.readFileSync(configPath, "utf-8")
    
    // 解析 JSONC（支持注释和尾随逗号）
    const rawConfig = parseJsonc<Record<string, unknown>>(content)
    
    // 执行配置迁移
    const wasMigrated = migrateConfigFile(configPath, rawConfig)
    
    if (wasMigrated) {
      console.log("配置已自动迁移，备份文件已创建")
    }
    
    return rawConfig
  } catch (error) {
    console.error("配置加载失败:", error)
    return null
  }
}

// 使用示例
const config = loadAndMigrateConfig("~/.config/opencode/oh-my-opencode.jsonc")
```
