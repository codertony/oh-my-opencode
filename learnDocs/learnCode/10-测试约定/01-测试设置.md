---

## 核心职责

测试设置模块承担着以下关键职责：

**配置管理**：通过 `bunfig.toml` 文件集中管理 Bun 测试运行器的全局配置，包括预加载脚本、测试模式、覆盖率设置等。这种集中式配置确保所有测试文件在一致的环境中运行。

**状态重置**：`test-setup.ts` 文件在每个测试用例执行前自动运行，负责清理和重置全局状态。这对于防止测试间的状态污染至关重要，特别是在处理单例模式、缓存机制和全局事件监听器时。

**Mock 隔离**：针对使用 `mock.module()` 的测试文件，实施严格的进程隔离策略。由于 Bun 的模块缓存机制，Mock 会在进程级别持久化，必须通过隔离运行来防止交叉污染。

**CI 集成**：与 GitHub Actions 工作流紧密配合，支持测试分割策略。Mock 密集型测试单独运行，其余测试批量执行，在保证隔离性的同时优化 CI 执行时间。

## Bun 测试配置

### 1. bunfig.toml 配置

`bunfig.toml` 是 Bun 的配置文件，位于项目根目录。它使用 TOML 格式定义测试行为：

```toml
[test]
preload = ["./test-setup.ts"]
```

**配置说明**：
- `[test]` 节：专门针对测试命令的配置
- `preload`：指定在每个测试文件执行前自动加载的脚本数组
- 路径 `"./test-setup.ts"` 相对于项目根目录解析

这种配置确保 `test-setup.ts` 中的逻辑在每个测试文件开始前执行，无需在每个测试文件中手动导入。

### 2. test-setup.ts 预加载

`test-setup.ts` 是测试基础设施的核心，负责全局状态管理：

```typescript
import { beforeEach } from "bun:test"
import { _resetForTesting as resetClaudeSessionState } from "./src/features/claude-code-session-state/state"
import { _resetForTesting as resetModelFallbackState } from "./src/hooks/model-fallback/hook"

beforeEach(() => {
  resetClaudeSessionState()
  resetModelFallbackState()
})
```

**代码解析**：
- 第 1 行：从 `bun:test` 导入 `beforeEach` 钩子
- 第 2-3 行：导入需要重置的模块状态重置函数
- 第 5-8 行：在每个测试用例执行前调用重置函数

**设计原则**：
- 使用 `beforeEach` 而非 `beforeAll`，确保每个测试用例都有干净的状态
- 重置函数以 `_resetForTesting` 命名，明确表示仅用于测试
- 集中管理所有需要重置的全局状态

### 3. Mock 隔离策略

Bun 的 `mock.module()` 会在进程级别缓存 Mock 实现，导致测试间污染。项目采用以下隔离策略：

**策略一：进程隔离**

在 CI 中，Mock 密集型测试单独运行：

```yaml
- name: Run mock-heavy tests (isolated)
  run: |
    bun test src/plugin-handlers
    bun test src/hooks/atlas
    bun test src/tools/session-manager
```

**策略二：显式恢复**

在每个测试文件的 `beforeEach` 中调用 `mock.restore()`：

```typescript
beforeEach(() => {
  mock.restore()  // 清除所有 Mock
  __resetModelCache()
})
```

**策略三：模块级隔离**

对于特别敏感的 Mock，在单独进程中运行整个测试文件。

## 测试设置流程

测试执行的完整流程如下：

1. **Bun 启动**：读取 `bunfig.toml` 配置
2. **预加载执行**：加载 `test-setup.ts`，注册全局 `beforeEach` 钩子
3. **测试文件加载**：导入测试文件，收集 `describe` 和 `test` 定义
4. **测试套件执行**：按顺序执行每个 `describe` 块
5. **前置钩子**：每个 `test` 前执行 `beforeEach` 钩子（状态重置）
6. **测试用例执行**：运行实际的测试逻辑
7. **断言验证**：检查 `expect` 断言结果
8. **后置清理**：准备下一个测试用例

## 依赖关系

测试设置模块与以下组件存在依赖关系：

**向上依赖**：
- Bun 运行时：提供 `bun:test` 模块和测试执行环境
- GitHub Actions：提供 CI 执行环境

**向下依赖**：
- Claude Code 会话状态：需要重置以避免测试间干扰
- 模型回退状态：需要重置以确保测试独立性
- 各功能模块的测试重置函数：通过 `_resetForTesting` 接口暴露

**同级依赖**：
- Given-When-Then 测试模式：测试编写风格约定
- Mock 隔离策略：与测试设置协同工作

## 实战示例

### 示例 1: 测试文件编写

以下是一个遵循项目测试约定的完整测试文件示例：

```typescript
// src/tools/example/tools.test.ts
declare const require: (name: string) => any
const { describe, test, expect, beforeEach } = require("bun:test")
import { processData } from "./tools"

describe("example-tool", () => {
  beforeEach(() => {
    // test-setup.ts 已自动运行，状态已重置
    // 此处可添加本文件特定的前置逻辑
  })

  describe("#given 输入数据", () => {
    describe("#when 处理有效数据", () => {
      test("#then 返回处理结果", () => {
        // given
        const input = { value: 42 }
        
        // when
        const result = processData(input)
        
        // then
        expect(result).toBe(84)
      })
    })

    describe("#when 处理无效数据", () => {
      test("#then 抛出错误", () => {
        // given
        const input = null
        
        // when/then
        expect(() => processData(input)).toThrow()
      })
    })
  })
})
```

### 示例 2: Mock 隔离使用

对于需要使用 `mock.module()` 的测试：

```typescript
// src/features/example/mock-heavy.test.ts
declare const require: (name: string) => any
const { describe, test, expect, beforeEach, mock } = require("bun:test")

// 标记：此文件需要在 CI 中单独运行
describe("mock-heavy-feature", () => {
  beforeEach(() => {
    // 必须显式恢复 Mock
    mock.restore()
  })

  test("应该 Mock 外部模块", () => {
    // 设置 Mock
    mock.module("./dependency", () => ({
      fetchData: () => Promise.resolve({ mocked: true })
    }))
    
    // 测试逻辑...
  })
})
```

**CI 配置**：

```yaml
- name: Run mock-heavy tests (isolated)
  run: |
    bun test src/features/example/mock-heavy.test.ts
```
