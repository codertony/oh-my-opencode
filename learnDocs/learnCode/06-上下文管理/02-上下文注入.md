上下文注入机制位于 Layer 3 的 Context 层，负责在工具执行过程中自动将项目相关的上下文文档注入到 AI 的会话中。这是 oh-my-opencode 实现"智能上下文感知"的核心组件。

---

## 核心职责

上下文注入机制的核心职责是在 AI 代理操作文件时，自动发现并注入相关的上下文文档。这种机制解决了传统 AI 编程助手"只见树木不见森林"的问题：当代理读取或修改某个文件时，它能自动获得该文件所在目录乃至整个项目的相关规则和说明。

具体来说，系统通过监听 `tool.execute.after` 事件，在 Read、Write、Edit、MultiEdit 等文件操作完成后，自动查找并注入三类上下文文档：AGENTS.md 提供目录级别的代理指导，Rules 文件提供条件化的规则匹配，README.md 提供项目说明。所有注入内容都经过动态截断处理，确保不会超出模型的上下文窗口限制，同时通过会话级缓存避免重复注入。

### 1. AGENTS.md 自动注入

```typescript
// src/hooks/directory-agents-injector/finder.ts:12-38
export function findAgentsMdUp(input: {
  startDir: string;
  rootDir: string;
}): string[] {
  const found: string[] = [];
  let current = input.startDir;

  while (true) {
    const isRootDir = current === input.rootDir;
    if (!isRootDir) {
      const agentsPath = join(current, AGENTS_FILENAME);
      if (existsSync(agentsPath)) {
        found.push(agentsPath);
      }
    }
    if (isRootDir) break;
    const parent = dirname(current);
    if (parent === current) break;
    if (!parent.startsWith(input.rootDir)) break;
    current = parent;
  }

  return found.reverse();
}
```

### 2. 条件规则注入

Rules 注入机制支持基于文件路径模式的条件匹配，只有符合特定 glob 模式的规则才会被注入。这允许为不同类型的文件定义专门的规则。

**Pattern Matching 机制**：

规则文件使用 YAML frontmatter 定义匹配条件（`src/hooks/rules-injector/matcher.ts:14-42`）：

```typescript
// src/hooks/rules-injector/matcher.ts:14-42
export function shouldApplyRule(
  metadata: RuleMetadata,
  currentFilePath: string,
  projectRoot: string | null
): MatchResult {
  if (metadata.alwaysApply === true) {
    return { applies: true, reason: "alwaysApply" };
  }

  const globs = metadata.globs;
  if (!globs) {
    return { applies: false };
  }

  const patterns = Array.isArray(globs) ? globs : [globs];
  const relativePath = projectRoot ? relative(projectRoot, currentFilePath) : currentFilePath;

  for (const pattern of patterns) {
    if (picomatch.isMatch(relativePath, pattern, { dot: true, bash: true })) {
      return { applies: true, reason: `glob: ${pattern}` };
    }
  }

  return { applies: false };
}
```

### 3. README.md 注入

README.md 注入机制与 AGENTS.md 类似，但专门针对项目说明文档。当代理读取项目中的文件时，会自动注入该目录层级中的 README.md 内容。

**查找逻辑**（`src/hooks/directory-readme-injector/finder.ts:12-33`）：

```typescript
export function findReadmeMdUp(input: {
  startDir: string;
  rootDir: string;
}): string[] {
  const found: string[] = [];
  let current = input.startDir;

  while (true) {
    const readmePath = join(current, README_FILENAME);
    if (existsSync(readmePath)) {
      found.push(readmePath);
    }

    if (current === input.rootDir) break;
    const parent = dirname(current);
    if (parent === current) break;
    if (!parent.startsWith(input.rootDir)) break;
    current = parent;
  }

  return found.reverse();
}
```

## 注入触发条件

上下文注入在以下条件下触发：

1. **工具触发**：当 `Read`、`Write`、`Edit`、`MultiEdit` 工具执行完成后（Rules 注入器监听这些工具）
2. **特定工具**：AGENTS.md 和 README.md 注入器仅在 `Read` 工具执行后触发
3. **会话级去重**：通过 `sessionCaches` 确保同一会话中同一目录的上下文只注入一次
4. **文件存在性**：只有当目标文件存在时才会触发注入

---

## 注入流程

完整的上下文注入流程如下：

1. **工具执行完成**：用户或代理执行文件操作工具
2. **Hook 触发**：`tool.execute.after` 事件触发注入器
3. **路径解析**：解析文件绝对路径，确定所在目录
4. **文件查找**：向上遍历目录树，查找 AGENTS.md、Rules、README.md 文件
5. **规则匹配**：对于 Rules，根据 glob 模式过滤匹配的规则
6. **去重检查**：检查会话缓存，避免重复注入
7. **内容截断**：使用 DynamicTruncator 根据模型上下文窗口截断内容
8. **内容注入**：将上下文内容追加到工具输出中
9. **缓存更新**：更新会话缓存，记录已注入的路径

### 片段 1: Rules 注入器核心逻辑

```typescript
// src/hooks/rules-injector/injector.ts:94-166
async function processFilePathForInjection(
  filePath: string,
  sessionID: string,
  output: ToolExecuteOutput
): Promise<void> {
  const resolved = resolveFilePath(workspaceDirectory, filePath);
  if (!resolved) return;

  const projectRoot = findProjectRoot(resolved);
  const cache = getSessionCache(sessionID);
  const home = homedir();

  const ruleFileCandidates = findRuleFiles(projectRoot, home, resolved);
  const toInject: RuleToInject[] = [];
  let dirty = false;

  for (const candidate of ruleFileCandidates) {
    if (isDuplicateByRealPath(candidate.realPath, cache.realPaths)) continue;

    const { metadata, body } = getCachedParsedRule(candidate.path, candidate.realPath);

    const matchResult = shouldApplyRule(metadata, resolved, projectRoot);
    if (!matchResult.applies) continue;

    const contentHash = createContentHash(body);
    if (isDuplicateByContentHash(contentHash, cache.contentHashes)) continue;

    toInject.push({
      relativePath,
      matchReason,
      content: body,
      distance: candidate.distance,
    });

    cache.realPaths.add(candidate.realPath);
    cache.contentHashes.add(contentHash);
    dirty = true;
  }

  // 按距离排序并注入
  toInject.sort((a, b) => a.distance - b.distance);
  for (const rule of toInject) {
    const { result, truncated } = await truncator.truncate(sessionID, rule.content);
    output.output += `\n\n[Rule: ${rule.relativePath}]\n[Match: ${rule.matchReason}]\n${result}`;
  }
}
```

```typescript
  metadata: RuleMetadata,
  currentFilePath: string,
  projectRoot: string | null

    return { applies: true, reason: "alwaysApply" };
```

## 依赖关系

上下文注入机制依赖以下组件：

## 实战示例

### 示例 1: 目录规则注入

假设项目结构如下：

```
my-project/
├── AGENTS.md              # 项目级规则
├── src/
│   ├── AGENTS.md          # src 目录规则
│   └── components/
│       ├── AGENTS.md      # 组件目录规则
│       └── Button.tsx
└── tests/
    └── Button.test.tsx
```

当代理读取 `src/components/Button.tsx` 时，系统会按以下顺序注入：

1. 首先注入 `src/components/AGENTS.md`（最近）
2. 然后注入 `src/AGENTS.md`
3. 最后注入 `my-project/AGENTS.md`（最远）

注入后的输出示例：

```
[Directory Context: /project/src/components/AGENTS.md]
# Components

All components must use TypeScript and follow the design system.

[Directory Context: /project/src/AGENTS.md]
# Source Code

Follow the modular architecture pattern. Each file should have a single responsibility.

[Directory Context: /project/AGENTS.md]
# My Project

This is a React application built with TypeScript.
```

### 示例 2: 自定义规则注入

在 `.claude/rules/` 目录下创建条件规则文件：

```markdown
---
globs: "**/*.test.ts"
alwaysApply: false
---

# Testing Guidelines

- Use descriptive test names
- Follow the AAA pattern (Arrange, Act, Assert)
- Mock external dependencies
```

当代理读取或编辑任何 `.test.ts` 文件时，该规则会自动注入：

```
[Rule: .claude/rules/testing.md]
[Match: glob: **/*.test.ts]
# Testing Guidelines

- Use descriptive test names
- Follow the AAA pattern (Arrange, Act, Assert)
- Mock external dependencies
```

如果规则不匹配当前文件（如读取 `.ts` 而非 `.test.ts`），则不会注入。
