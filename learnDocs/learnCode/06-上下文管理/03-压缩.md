上下文压缩与恢复模块位于三层架构的最顶层（Layer 3），负责在会话上下文达到限制时进行智能压缩，并在压缩后恢复关键的会话状态，确保长时间对话的连续性。

## 核心职责

上下文压缩与恢复机制是 Oh My OpenCode 插件中保障长会话稳定运行的关键组件。当 AI 会话的上下文窗口接近或达到模型限制时，系统会自动触发压缩流程，将历史消息总结为紧凑的摘要，同时保留关键的会话状态信息。

该模块的核心职责包括三个方面：首先，**压缩触发**负责监听会话状态，在检测到上下文窗口压力或收到 `session.compacted` 事件时启动压缩流程；其次，**上下文保留**在压缩前捕获当前的 Agent 配置、模型设置、工具权限以及待办事项状态，将这些关键信息保存到内存中的 Checkpoint；最后，**恢复注入**在压缩完成后，将保留的上下文信息重新注入到会话中，确保 Agent 能够无缝继续之前的任务，不会出现身份丢失或状态重置的问题。

这种机制特别适用于需要长时间运行的复杂任务，如代码重构、大型功能开发或多轮调试会话，能够有效避免因上下文溢出而导致的中断。

## 上下文压缩机制

### 1. 压缩触发

压缩触发机制通过监听 OpenCode 的会话事件来检测何时需要进行上下文恢复。主要触发条件有两个：

**事件驱动触发**：当 OpenCode 触发 `session.compacted` 事件时，表示会话历史已被压缩，此时需要执行恢复流程。

**无文本尾部检测**：当检测到连续多条助手消息没有文本输出时（默认阈值为 5 条），系统会检查是否在最近的压缩窗口期内（10 分钟），如果是，则尝试恢复配置。

```typescript
// src/hooks/compaction-context-injector/hook.ts:95-107
if (event.type === "session.compacted") {
  const sessionID = resolveSessionID(props)
  if (!sessionID) {
    return
  }

  const tailState = getTailState(sessionID)
  finalizeTrackedAssistantMessage(tailState)
  tailState.lastCompactedAt = Date.now()
  await maybeWarnAboutNoTextTail(sessionID)
  await recoverCheckpointedAgentConfig(sessionID, "session.compacted")
  return
}
```

### 2. 上下文保留

在压缩发生前，系统会捕获当前会话的关键配置信息并保存到 Checkpoint。保留的信息包括：

- **Agent 标识**：当前运行的 Agent 名称（如 sisyphus、hephaestus 等）
- **模型配置**：当前使用的模型提供商和模型 ID
- **工具权限**：当前会话可用的工具及其启用状态

```typescript
// src/hooks/compaction-context-injector/hook.ts:38-55
const capture = async (sessionID: string): Promise<void> => {
  if (!ctx || !sessionID) {
    return
  }

  const promptConfig = await resolveSessionPromptConfig(ctx, sessionID)
  if (!promptConfig.agent && !promptConfig.model && !promptConfig.tools) {
    return
  }

  setCompactionAgentConfigCheckpoint(sessionID, promptConfig)
  log(`[compaction-context-injector] Captured agent checkpoint before compaction`, {
    sessionID,
    agent: promptConfig.agent,
    model: promptConfig.model,
    hasTools: !!promptConfig.tools,
  })
}
```

Checkpoint 数据存储在内存中的 Map 结构中，以 sessionID 为键：

```typescript
// src/shared/compaction-agent-config-checkpoint.ts:26-31
export function setCompactionAgentConfigCheckpoint(
  sessionID: string,
  checkpoint: CompactionAgentConfigCheckpoint,
): void {
  checkpoints.set(sessionID, cloneCheckpoint(checkpoint))
}
```

### 3. 恢复注入

压缩完成后，恢复注入器会执行以下步骤来恢复会话状态：

1. **验证 Checkpoint**：检查是否存在有效的 Checkpoint 数据
2. **冷却检查**：确保距离上次恢复已超过冷却时间（默认 60 秒）
3. **模型验证**：验证 Checkpoint 中的模型是否与当前配置兼容
4. **配置注入**：通过 `promptAsync` API 将会话配置重新注入
5. **状态确认**：验证恢复后的配置是否匹配预期
6. **状态更新**：更新会话状态存储（Agent、模型、工具）

```typescript
// src/hooks/compaction-context-injector/recovery.ts:79-123
try {
  await ctx.client.session.promptAsync({
    path: { id: sessionID },
    body: {
      noReply: true,
      agent: expectedPromptConfig.agent,
      ...(model ? { model } : {}),
      ...(tools ? { tools } : {}),
      parts: [createInternalAgentTextPart(AGENT_RECOVERY_PROMPT)],
    },
    query: { directory: ctx.directory },
  })

  // 验证恢复是否成功
  const recoveredPromptConfig = await resolveLatestSessionPromptConfig(ctx, sessionID)
  if (!isPromptConfigRecovered(recoveredPromptConfig, expectedPromptConfig)) {
    log(`[compaction-context-injector] Re-injected agent config but recovery is still incomplete`, {
      sessionID,
      reason,
      agent: expectedPromptConfig.agent,
      model,
      hasTools: !!tools,
      recoveredPromptConfig,
    })
    return false
  }

  // 更新会话状态
  updateSessionAgent(sessionID, expectedPromptConfig.agent)
  if (model) {
    setSessionModel(sessionID, model)
  }
  if (tools) {
    setSessionTools(sessionID, tools)
  }

  tailState.lastRecoveryAt = now
  tailState.consecutiveNoTextMessages = 0

  return true
}
```

## 压缩流程

上下文压缩与恢复的完整流程如下：

1. **预压缩阶段**：系统检测到上下文压力，准备执行压缩
2. **配置捕获**：`capture` 方法被调用，保存当前 Agent、模型、工具配置到 Checkpoint
3. **压缩执行**：OpenCode 执行实际的上下文压缩，将历史消息总结为摘要
4. **压缩完成**：触发 `session.compacted` 事件
5. **恢复判断**：检查 Checkpoint 是否存在、冷却时间是否已过
6. **配置注入**：调用 `promptAsync` 将保存的配置重新注入会话
7. **状态验证**：确认恢复后的配置与预期一致
8. **状态同步**：更新本地会话状态存储

### 片段 1: Checkpoint 数据结构与管理

```typescript
// src/shared/compaction-agent-config-checkpoint.ts:1-42
export type CompactionAgentConfigCheckpoint = {
  agent?: string
  model?: { providerID: string; modelID: string }
  tools?: Record<string, boolean>
}

const checkpoints = new Map<string, CompactionAgentConfigCheckpoint>()

export function setCompactionAgentConfigCheckpoint(
  sessionID: string,
  checkpoint: CompactionAgentConfigCheckpoint,
): void {
  checkpoints.set(sessionID, cloneCheckpoint(checkpoint))
}

export function getCompactionAgentConfigCheckpoint(
  sessionID: string,
): CompactionAgentConfigCheckpoint | undefined {
  const checkpoint = checkpoints.get(sessionID)
  return checkpoint ? cloneCheckpoint(checkpoint) : undefined
}

export function clearCompactionAgentConfigCheckpoint(sessionID: string): void {
  checkpoints.delete(sessionID)
}
```

### 片段 2: 恢复配置匹配验证

```typescript
// src/hooks/compaction-context-injector/recovery-prompt-config.ts:61-76
export function isPromptConfigRecovered(
  actualPromptConfig: CompactionAgentConfigCheckpoint,
  expectedPromptConfig: RecoveryPromptConfig,
): boolean {
  const actualAgent = actualPromptConfig.agent
  const agentMatches =
    typeof actualAgent === "string" &&
    !isCompactionAgent(actualAgent) &&
    actualAgent.toLowerCase() === expectedPromptConfig.agent.toLowerCase()

  return (
    agentMatches &&
    matchesExpectedModel(actualPromptConfig.model, expectedPromptConfig.model) &&
    matchesExpectedTools(actualPromptConfig.tools, expectedPromptConfig.tools)
  )
}
```

## 实战示例

### 示例 1: 长对话压缩

**场景**：用户正在使用 Sisyphus Agent 进行一个大型代码重构任务，会话已经进行了 2 小时，上下文窗口接近限制。

**流程**：

1. 系统检测到上下文压力，触发预压缩流程
2. `capture` 方法被调用，保存当前配置：
   ```typescript
   {
     agent: "sisyphus",
     model: { providerID: "anthropic", modelID: "claude-opus-4-6" },
     tools: { "read": true, "edit": true, "bash": true, "delegate_task": true }
   }
   ```
3. OpenCode 压缩历史消息，生成摘要
4. 触发 `session.compacted` 事件
5. 恢复注入器检测到事件，执行恢复流程
6. 会话继续运行，Agent 仍然是 Sisyphus，模型和工具配置保持不变
7. 用户无感知地继续之前的重构任务

### 示例 2: 压缩后恢复

**场景**：在一次压缩后，用户发现 Agent 响应异常，似乎回到了默认配置。

**诊断与恢复**：

1. 检查日志发现 `consecutiveNoTextMessages` 达到阈值 5
2. 系统检测到最近的压缩事件（在 10 分钟窗口内）
3. 自动触发 `recoverCheckpointedAgentConfig` 方法
4. 验证 Checkpoint 发现保存的 Agent 是 "hephaestus"
5. 但当前会话配置显示为默认 Agent
6. 执行恢复注入，重新设置 Agent 为 "hephaestus"
7. 验证恢复成功，会话恢复正常

**关键日志输出**：
```
[compaction-context-injector] Detected consecutive assistant messages with no text
  sessionID: "sess_abc123"
  consecutiveNoTextMessages: 5
  recentlyCompacted: true

[compaction-context-injector] Re-injected checkpointed agent config
  sessionID: "sess_abc123"
  reason: "no-text-tail"
  agent: "hephaestus"
  model: { providerID: "openai", modelID: "gpt-5.4" }
```
