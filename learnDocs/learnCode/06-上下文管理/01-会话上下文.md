会话上下文管理位于应用层（Layer 3），负责维护每个会话的独立状态空间，确保多会话并发执行时的状态隔离与数据一致性。

---

## 核心职责

会话上下文管理模块承担以下核心职责：

**状态隔离**：为每个会话维护独立的状态空间，包括工具可用性、模型配置、提示参数等。通过 `sessionID` 作为键值，确保不同会话之间的状态互不干扰，支持多会话并行执行。

**上下文持久化**：管理会话级别的数据持久化，包括注入路径追踪、待办事项状态、模型缓存等。提供内存存储与文件存储的混合策略，平衡性能与可靠性。

**生命周期管理**：监听会话创建、更新、删除事件，自动执行状态清理与资源回收。通过 TTL 机制与定期修剪，防止内存泄漏与无界增长。

**上下文注入**：支持在会话执行过程中动态注入上下文信息，如 AGENTS.md、README.md 等文档内容，以及系统指令与规则。

## 会话上下文机制

### 1. 每会话状态

每会话状态（Per-Session State）是会话上下文管理的基础。系统通过 `Map<string, State>` 数据结构，以 `sessionID` 为键存储每个会话的独立状态。

```typescript
// src/shared/session-tools-store.ts
const store = new Map<string, Record<string, boolean>>();

export function setSessionTools(sessionID: string, tools: Record<string, boolean>): void {
  store.set(sessionID, { ...tools });
}

export function getSessionTools(sessionID: string): Record<string, boolean> | undefined {
  const tools = store.get(sessionID);
  return tools ? { ...tools } : undefined;
}
```

每会话状态包含以下类型：

- **工具状态**（`session-tools-store.ts`）：记录每个会话中可用/禁用的工具
- **模型状态**（`session-model-state.ts`）：存储会话绑定的 providerID 与 modelID
- **提示参数**（`session-prompt-params-state.ts`）：温度、topP 等生成参数
- **游标位置**（`session-cursor.ts`）：消息消费进度，支持增量读取

### 2. 上下文存储

上下文存储采用分层策略，结合内存缓存与文件持久化：

**内存存储**：使用 JavaScript `Map` 对象实现 O(1) 访问速度，适用于高频读写的临时状态。

```typescript
// src/shared/session-model-state.ts
```

**文件持久化**：对于需要跨进程保留的数据，使用 JSON 文件存储：

```typescript
// src/shared/session-injected-paths.ts
```

**TTL 与修剪**：为防止内存泄漏，系统实现了自动修剪机制：

```typescript
// src/hooks/todo-continuation-enforcer/session-state.ts
const SESSION_STATE_TTL_MS = 10 * 60 * 1000;  // 10 分钟 TTL
const SESSION_STATE_PRUNE_INTERVAL_MS = 2 * 60 * 1000;  // 每 2 分钟修剪

pruneInterval = setInterval(() => {
  const now = Date.now();
  for (const [sessionID, tracked] of sessions.entries()) {
    if (now - tracked.lastAccessedAt > SESSION_STATE_TTL_MS) {
      cancelCountdown(sessionID);
      sessions.delete(sessionID);
    }
```

**增量消费**：会话游标机制支持增量读取新消息，避免重复处理：

```typescript
// src/shared/session-cursor.ts
export function consumeNewMessages<T extends CursorMessage>(
  sessionID: string | undefined,
  messages: T[]
): T[] {
  if (!sessionID) return messages;

  const keys = messages.map((message, index) => buildMessageKey(message, index));
  const cursor = sessionCursors.get(sessionID);
  let startIndex = 0;

  if (cursor && cursor.lastKey) {
    const lastIndex = keys.lastIndexOf(cursor.lastKey);
    if (lastIndex >= 0) {
      startIndex = lastIndex + 1;
    }
  }

  sessionCursors.set(sessionID, {
    lastKey: keys[keys.length - 1],
    lastCount: messages.length,
  });

  return messages.slice(startIndex);
}
```

## 上下文管理流程

会话上下文管理遵循以下生命周期流程：

1. **初始化阶段**：会话创建时，系统初始化该会话的状态容器，包括工具状态、模型配置、提示参数等。

2. **运行阶段**：会话执行过程中，钩子与工具通过 `sessionID` 读写上下文状态。上下文窗口监控器跟踪 Token 使用量，在达到阈值时发出提醒。

3. **空闲检测**：当会话进入空闲状态时，系统检查待办事项完成状态。如有未完成的待办，触发 Boulder 机制强制继续执行。

4. **清理阶段**：会话删除时，系统清理该会话的所有状态数据，包括内存缓存与文件存储，释放资源。

### 片段 2: 上下文窗口监控

```typescript
// src/hooks/context-window-monitor.ts
export function createContextWindowMonitorHook(
  _ctx: PluginInput,
  modelCacheState?: ContextLimitModelCacheState,
) {
  const remindedSessions = new Set<string>()
  const tokenCache = new Map<string, CachedTokenState>()

  const toolExecuteAfter = async (
    input: { tool: string; sessionID: string; callID: string },
    output: { title: string; output: string; metadata: unknown }
  ) => {
    const { sessionID } = input
    if (remindedSessions.has(sessionID)) return

    const cached = tokenCache.get(sessionID)
    if (!cached) return

    const actualLimit = resolveActualContextLimit(
      cached.providerID,
      cached.modelID,
      modelCacheState,
    )

    const totalInputTokens = (cached.tokens?.input ?? 0) + (cached.tokens?.cache?.read ?? 0)
    const actualUsagePercentage = totalInputTokens / actualLimit

    if (actualUsagePercentage < CONTEXT_WARNING_THRESHOLD) return

    remindedSessions.add(sessionID)
    output.output += `\n\n${createContextReminder(actualLimit)}`
  }
}
```

### 片段 3: 会话消息格式化

```typescript
// src/tools/session-manager/session-formatter.ts
export function formatSessionMessages(
  messages: SessionMessage[],
  includeTodos?: boolean,
  todos?: Array<{ id?: string; content: string; status: string }>
): string {
  if (messages.length === 0) {
    return "No messages found in this session."
  }

  const lines: string[] = []

  for (const msg of messages) {
    const timestamp = msg.time?.created ? new Date(msg.time.created).toISOString() : "Unknown time"
    const agent = msg.agent ? ` (${msg.agent})` : ""
    lines.push(`\n[${msg.role}${agent}] ${timestamp}`)

    for (const part of msg.parts) {
      if (part.type === "text" && part.text) {
        lines.push(part.text.trim())
      } else if (part.type === "thinking" && part.thinking) {
        lines.push(`[thinking] ${part.thinking.substring(0, 200)}...`)
      } else if ((part.type === "tool_use" || part.type === "tool") && part.tool) {
        const input = part.input ? JSON.stringify(part.input).substring(0, 100) : ""
        lines.push(`[tool: ${part.tool}] ${input}`)
      }
    }
  }

  return lines.join("\n")
}
```

```typescript
import { getSessionModel } from "../shared/session-model-state";
import { getSessionPromptParams } from "../shared/session-prompt-params-state";

export function createCustomHook(ctx: PluginInput) {
  const eventHandler = async ({ event }: { event: { type: string; properties?: unknown } }) => {
    if (event.type === "message.updated") {
      const props = event.properties as { sessionID?: string; providerID?: string; modelID?: string };
      const sessionID = props?.sessionID;

      const params = getSessionPromptParams(sessionID);
      if (params?.temperature) {
        console.log(`Temperature: ${params.temperature}`);
      }
    }
  };

  return { event: eventHandler };
}
```

```typescript
export async function handleBackgroundTaskComplete(
  parentSessionID: string,

// 在父会话中检索后台任务结果
export async function retrieveBackgroundResults(
  sessionID: string,
  taskID: string
) {

    full_session: true,
```
