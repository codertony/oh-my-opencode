## 核心职责

会话持久化模块承担着 4 大核心职责：会话状态管理、消息存储与检索、会话恢复机制、以及跨会话搜索能力。它是 OMO 插件的"记忆系统"，让代理能够"记住"之前的对话、"找回"丢失的上下文、"继续"中断的任务。

会话状态管理负责追踪每个会话的元数据，包括消息数量、时间范围、使用的代理类型等。消息存储机制采用双后端设计：稳定模式使用 JSON 文件系统，Beta 模式使用 OpenCode SDK 的 SQLite 后端。会话恢复机制是 OMO 的独特能力，当会话因错误中断时，能够自动检测错误类型、重建消息状态、恢复会话执行。跨会话搜索则允许代理在历史会话中查找相关信息，实现知识的跨会话复用。

## 会话状态管理

会话状态管理是 Harness 层的基础能力。每个会话在创建时会被分配唯一的 Session ID，所有相关数据都以此 ID 为键进行存储。

### 会话元数据结构

```typescript
// src/tools/session-manager/types.ts:52-68
interface SessionMetadata {
  id: string
  version?: string
  projectID: string
  directory: string
  title?: string
  parentID?: string
  time: {
    created: number
    updated: number
  }
  summary?: {
    additions: number
    deletions: number
    files: number
  }
}
```

`parentID` 字段用于标识子会话关系。当代理通过 `task()` 工具创建后台任务时，新会话会记录父会话 ID，形成会话树结构。这种设计允许代理追踪任务的完整调用链。

### 双后端存储策略

OMO 支持两种存储后端：

1. **JSON 文件模式（稳定模式）**：会话数据存储在文件系统中
   - 会话元数据：`~/.config/opencode/sessions/{project}/{session}.json`
   - 消息数据：`~/.config/opencode/messages/{session}/{message}.json`
   - 消息部件：`~/.config/opencode/parts/{message}/{part}.json`

2. **SQLite 模式（Beta 模式）**：通过 OpenCode SDK 访问数据
   - 使用 `ctx.client.session.list()` 获取会话列表
   - 使用 `ctx.client.session.messages()` 读取消息
   - 使用 `ctx.client.session.todo()` 读取 Todo 列表

存储模式通过 `isSqliteBackend()` 函数自动检测，代码会根据检测结果选择相应的数据访问路径。

## 消息存储机制

消息是会话的核心数据单元。每条消息包含角色（user/assistant）、时间戳、代理标识和多个内容部件。

### 消息数据结构

```typescript
// src/tools/session-manager/types.ts:1-22
interface SessionMessage {
  id: string
  role: "user" | "assistant"
  agent?: string
  time?: {
    created: number
    updated?: number
  }
  parts: MessagePart[]
}

interface MessagePart {
  id: string
  type: string
  text?: string
  thinking?: string
  tool?: string
  callID?: string
  input?: Record<string, unknown>
  output?: string
  error?: string
}
```

`parts` 数组支持多种内容类型：
- `text`：普通文本内容
- `thinking`：代理的思考过程
- `tool_use`：工具调用请求
- `tool_result`：工具执行结果

### 消息读取流程

## 4 个会话工具

OMO 提供 4 个会话管理工具，让代理能够查询和利用历史会话数据。

### 1. session_list

列出所有可用的 OpenCode 会话，支持按日期和项目路径过滤。

**功能说明**：
- 返回会话 ID、消息数量、时间范围、使用的代理列表
- 支持 `from_date` 和 `to_date` 参数进行日期过滤
- 支持 `project_path` 参数按项目路径过滤
- 支持 `limit` 参数限制返回数量

**代码实现**：

```typescript
// src/tools/session-manager/tools.ts:34-61
```

### 2. session_read

读取指定会话的完整消息历史，可选包含 Todo 列表和转录日志。

**功能说明**：
- 返回格式化的消息历史，包含角色、时间戳和内容
- 支持 `include_todos` 参数包含 Todo 列表
- 支持 `include_transcript` 参数包含转录日志
- 支持 `limit` 参数限制返回消息数量

**代码实现**：

```typescript
// src/tools/session-manager/tools.ts:63-94
const session_read: ToolDefinition = tool({
  description: SESSION_READ_DESCRIPTION,
  args: {
    session_id: tool.schema.string().describe("Session ID to read"),
    include_todos: tool.schema.boolean().optional().describe("Include todo list if available"),
    include_transcript: tool.schema.boolean().optional().describe("Include transcript log if available"),
    limit: tool.schema.number().optional().describe("Maximum number of messages to return"),
  },
  execute: async (args: SessionReadArgs, _context) => {
    if (!(await sessionExists(args.session_id))) {
      return `Session not found: ${args.session_id}`
    }
    let messages = await readSessionMessages(args.session_id)
    const todos = args.include_todos ? await readSessionTodos(args.session_id) : undefined
    return formatSessionMessages(messages, args.include_todos, todos)
  },
})
```

### 3. session_search

在会话消息中搜索指定内容，支持跨会话搜索或限定单个会话。

**功能说明**：
- 全文搜索会话消息内容
- 支持 `session_id` 参数限定搜索范围
- 支持 `case_sensitive` 参数控制大小写敏感
- 默认最多扫描 50 个会话，返回最多 20 条结果
- 60 秒超时保护

**代码实现**：

```typescript

      }
      // 跨会话搜索
      const allSessions = await getAllSessions()
      const sessionsToScan = allSessions.slice(0, MAX_SESSIONS_TO_SCAN)
      // ... 遍历搜索
    }
    const results = await withTimeout(searchOperation(), SEARCH_TIMEOUT_MS, "Search")
    return formatSearchResults(results)
  },
})
```

获取会话的元数据和统计信息。

**功能说明**：
- 返回消息数量、时间范围、持续时间
- 列出会话中使用的代理类型
- 报告是否存在 Todo 列表和转录日志
- 统计 Todo 完成情况和转录条目数

**代码实现**：

### 片段 1：会话恢复错误检测

```typescript
// src/hooks/session-recovery/detect-error-type.ts:1-50
export type RecoveryErrorType =
  | "tool_result_missing"
  | "unavailable_tool"
  | "thinking_block_order"
  | "thinking_disabled_violation"
  | "assistant_prefill_unsupported"

export function detectErrorType(error: unknown): RecoveryErrorType | null {
  if (!error || typeof error !== "object") return null

  const errorMessage = String((error as { message?: string }).message || "")
  const errorString = String(error)

  // Tool result missing: tool was called but result not found
  if (
    errorMessage.includes("tool result") &&
    (errorMessage.includes("missing") || errorMessage.includes("not found"))
  ) {
    return "tool_result_missing"
  }

  // Unavailable tool: tool name not recognized
  if (
    errorMessage.includes("unavailable_tool") ||
    errorMessage.includes("tool is not available") ||
    errorMessage.includes("does not exist")
  ) {
    return "unavailable_tool"
  }

  // Thinking block order: thinking blocks in wrong position
  if (
    errorMessage.includes("thinking") &&
    (errorMessage.includes("order") || errorMessage.includes("position"))
  ) {
    return "thinking_block_order"
  }

  // ... more error types
}
```

```typescript
function withTimeout<T>(promise: Promise<T>, ms: number, operation: string): Promise<T> {
  return Promise.race([
    promise,
    new Promise<T>((_, reject) => 
      setTimeout(() => reject(new Error(`${operation} timed out after ${ms}ms`)), ms)
    ),
  ])
}
```

### 片段 3：会话信息格式化

```typescript
// src/tools/session-manager/session-formatter.ts:86-106
export function formatSessionInfo(info: SessionInfo): string {
  const lines = [
    `Session ID: ${info.id}`,
    `Messages: ${info.message_count}`,
    `Date Range: ${info.first_message?.toISOString() ?? "N/A"} to ${info.last_message?.toISOString() ?? "N/A"}`,
    `Agents Used: ${info.agents_used.join(", ") || "none"}`,
    `Has Todos: ${info.has_todos ? `Yes (${info.todos?.length ?? 0} items)` : "No"}`,
    `Has Transcript: ${info.has_transcript ? `Yes (${info.transcript_entries} entries)` : "No"}`,
  ]

  if (info.first_message && info.last_message) {
    const duration = info.last_message.getTime() - info.first_message.getTime()
    const days = Math.floor(duration / (1000 * 60 * 60 * 24))
    const hours = Math.floor((duration % (1000 * 60 * 60 * 24)) / (1000 * 60 * 60))
    if (days > 0 || hours > 0) {
      lines.push(`Duration: ${days} days, ${hours} hours`)
    }
  }

  return lines.join("\n")
}
```

## 依赖关系

会话持久化模块与 Harness 层的其他组件存在以下依赖关系：

```
Session Manager (会话管理)
    │
    ├──▶ Storage Backend (存储后端)
    │       ├── JSON File System
    │       └── OpenCode SDK (SQLite)
    │
    ├──▶ Session Recovery (会话恢复)
    │       ├── Error Detection
    │       ├── Message Rebuild
    │       └── Session Resume
    │
    ├──▶ Tool Registry (工具注册)
    │       └── 4 session tools registration
    │
    └──▶ Context Injector (上下文注入)
            └── Session history for context
```

**依赖说明**：

1. **Storage Backend**：会话管理依赖存储后端进行数据持久化。双后端设计提供了灵活性和兼容性。

2. **Session Recovery**：当会话发生错误时，恢复机制依赖会话管理工具读取和重建消息状态。

3. **Tool Registry**：4 个会话工具需要通过工具注册系统暴露给代理使用。

4. **Context Injector**：上下文注入器可能会使用会话历史来增强代理的上下文理解。

**场景**：用户正在开发一个功能，想查找之前会话中关于"authentication"的讨论。

**执行流程**：

   ```typescript
   session_search({

     case_sensitive: false,
     limit: 10
   })
   ```

2. **搜索执行**：
   - `session_search` 工具调用 `getAllSessions()` 获取所有会话 ID
   - 最多扫描 50 个最近会话
   - 对每个会话调用 `searchInSession()` 进行内容匹配

3. **结果返回**：
   ```
   Found 3 matches across 2 sessions:

   [ses_abc123] Message msg_001 (user) 2025-03-20T10:30:00
   ...implement the **authentication** middleware...

   [ses_abc123] Message msg_005 (assistant) 2025-03-20T10:35:00
   ...I'll create an **authentication** system with JWT...

   [ses_def456] Message msg_012 (user) 2025-03-21T14:20:00
   ...use the **authentication** pattern from yesterday...
   ```

4. **代理读取相关会话**：
   ```typescript
   session_read({
     session_id: "ses_abc123",
   ```

5. **知识复用**：代理基于历史会话中的实现方案，继续当前任务的开发。

### 示例 2: 会话恢复机制

**场景**：Sisyphus 代理在执行任务时遇到"thinking block order"错误，会话中断。

**恢复流程**：

1. **错误发生**：OpenCode 触发 `session.error` 事件

2. **错误检测**：`detectErrorType()` 识别为 `thinking_block_order`

3. **恢复钩子执行**：`handleSessionRecovery()` 被调用
   ```typescript
   // src/hooks/session-recovery/hook.ts:50-142
   const handleSessionRecovery = async (info: MessageInfo): Promise<boolean> => {
     // 检测错误类型
     const errorType = detectErrorType(info.error)
     if (!errorType) return false

     // 中止当前会话
     await ctx.client.session.abort({ path: { id: sessionID } })

     // 获取会话消息
     const messagesResp = await ctx.client.session.messages({
       path: { id: sessionID },
       query: { directory: ctx.directory },
     })

     // 显示恢复通知
     await ctx.client.tui.showToast({
       title: "Thinking Block Recovery",
       message: "Fixing message structure...",
       variant: "warning",
       duration: 3000,
     })

     // 执行具体恢复策略
     if (errorType === "thinking_block_order") {
       success = await recoverThinkingBlockOrder(...)
     }

     // 自动恢复会话（如果启用）
     if (success && experimental?.auto_resume) {
       await resumeSession(ctx.client, resumeConfig)
     }
   }
   ```

4. **消息重建**：`recoverThinkingBlockOrder` 修复思考块的顺序问题

5. **会话恢复**：如果配置了 `auto_resume`，自动恢复会话执行
