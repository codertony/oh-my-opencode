工具层位于 Harness 三层模型的最底层，直接暴露给 OpenCode Core 和 Agent 层调用。它是插件与外部世界交互的接口层，所有文件操作、代码搜索、任务委托等功能都通过这一层的 26 个工具实现。

---

## 核心职责

工具层的核心职责是将插件的复杂功能封装为标准化的 ToolDefinition 接口，供 OpenCode 的 LLM 调用。每个工具都遵循统一的工厂模式创建，支持参数校验、执行前钩子、执行后钩子的完整生命周期。

工具层采用"工厂函数优先"的设计哲学：19 个工具通过 `createXXXTool()` 工厂函数动态创建，7 个工具（主要是 LSP 相关）直接导出静态的 ToolDefinition。这种区分基于工具是否需要运行时上下文注入。工厂函数可以接收 PluginContext、Managers、Config 等依赖，而静态导出适用于无状态的工具。

工具注册流程在 `createToolRegistry()` 中完成，它会按顺序组装所有工具，应用 `disabled_tools` 过滤，最后返回可供 OpenCode 使用的工具映射表。整个流程支持条件性工具启用（如 task_system、hashline_edit 等实验性功能）和动态工具预算控制（max_tools 限制）。

## 26 个工具分类

### 1. LSP Refactoring (6 个工具)

LSP 工具提供 IDE 级别的代码重构能力，直接操作语言服务器协议：

| 工具名 | 用途 |
|--------|------|
| `lsp_goto_definition` | 跳转到符号定义位置 |
| `lsp_find_references` | 查找符号的所有引用 |
| `lsp_symbols` | 获取文件或工作区的符号列表 |
| `lsp_diagnostics` | 获取文件的诊断信息（错误/警告） |
| `lsp_prepare_rename` | 检查重命名是否有效 |
| `lsp_rename` | 执行符号重命名重构 |

这 6 个工具采用**直接导出模式**，在 `src/tools/lsp/index.ts` 中作为静态对象导出，通过 `builtinTools` 对象批量注册。

### 2. Code Search (4 个工具)

代码搜索工具支持多种搜索模式，从文本匹配到 AST 感知：

| 工具名 | 用途 |
|--------|------|
| `grep` | 正则内容搜索（60s 超时，10MB 限制） |
| `glob` | 文件模式匹配（60s 超时，100 文件限制） |
| `ast_grep_search` | AST 感知代码搜索（支持 25 种语言） |
| `ast_grep_replace` | AST 感知代码替换 |

AST-Grep 工具使用元变量（`$VAR`、`$$$`）进行模式匹配，支持在 25 种编程语言中进行语义级代码操作。

### 3. Session History (4 个工具)

会话管理工具允许 Agent 查询历史会话：

| 工具名 | 用途 |
|--------|------|
| `session_list` | 列出所有可用会话 |
| `session_read` | 读取特定会话的消息历史 |
| `session_search` | 搜索会话内容 |
| `session_info` | 获取会话元数据 |

这些工具使 Agent 能够进行跨会话的上下文恢复和知识检索。

### 4. Background Tasks (2 个工具)

后台任务工具支持并行 Agent 执行：

| 工具名 | 用途 |
|--------|------|
| `background_output` | 获取后台任务输出（支持轮询和阻塞模式） |
| `background_cancel` | 取消运行中的后台任务 |

通过 `createBackgroundTools()` 工厂函数创建，依赖 BackgroundManager 进行任务生命周期管理。

### 5. Task Management (4 个工具)

任务系统工具提供结构化任务跟踪（实验性功能，默认启用）：

| 工具名 | 用途 |
|--------|------|
| `task_create` | 创建新任务 |
| `task_get` | 获取任务详情 |
| `task_list` | 列出所有任务 |
| `task_update` | 更新任务状态 |

由 `experimental.task_system` 配置控制启用，支持任务依赖图和并行执行规划。

### 6. Agent Invocation (2 个工具)

Agent 调用工具是 Harness 的核心编排机制：

| 工具名 | 用途 |
|--------|------|
| `task` | 委托任务给子 Agent（支持 category/subagent_type） |
| `call_omo_agent` | 直接调用特定 OMO Agent |

`task` 工具是最复杂的工具，支持 8 个内置分类（visual-engineering、ultrabrain、deep 等），每个分类映射到特定的模型配置。

### 7. Skill System (2 个工具)

技能系统工具支持动态加载领域知识：

| 工具名 | 用途 |
|--------|------|
| `skill` | 执行内置或自定义技能 |
| `skill_mcp` | 调用技能嵌入的 MCP 服务器 |

技能可以携带自己的 MCP 服务器配置，实现按需启动、任务完成后关闭的资源管理模式。

### 8. System (2 个工具)

系统工具提供基础运行时能力：

| 工具名 | 用途 |
|--------|------|
| `interactive_bash` | Tmux 交互式终端（支持 REPL、调试器、TUI） |
| `look_at` | 多模态图像分析（依赖 Multimodal-Looker Agent） |

`interactive_bash` 是唯一的直接导出系统工具，提供完整的终端交互能力。

## 工具注册流程

`createToolRegistry()` 函数（`src/plugin/tool-registry.ts:43-190`）是工具层的核心组装器：

```
创建流程：
1. 创建后台任务工具 (createBackgroundTools)
2. 创建 Agent 调用工具 (createCallOmoAgent)
3. 条件创建 look_at (检查 disabled_agents)
4. 创建任务委托工具 (createDelegateTask)
5. 创建技能 MCP 工具 (createSkillMcpTool)
6. 发现可用命令 (discoverCommandsSync)
7. 创建技能工具 (createSkillTool)
8. 条件创建任务系统工具 (task_create/get/list/update)
9. 条件创建 hashline_edit (hashline_edit 配置)
10. 合并所有工具到 allTools 对象
11. 规范化所有工具的参数 schema
12. 应用 disabled_tools 过滤
13. 应用 max_tools 预算限制
14. 返回 filteredTools 和 taskSystemEnabled
```

每个步骤都遵循依赖注入原则，从外部接收必要的上下文和配置。

工具层使用两种创建模式：

### 模式一：工厂函数（19 个工具）

适用于需要运行时上下文的工具：


工厂函数接收依赖参数，返回配置完成的 ToolDefinition 对象。

### 模式二：直接导出（7 个工具）

适用于无状态的静态工具：

```typescript

  lsp_rename,

```

LSP 工具直接导出，因为它们只依赖全局的 LSPManager，不需要额外的运行时配置。

## 工具过滤机制

`disabled_tools` 配置通过 `filterDisabledTools()` 函数（`src/shared/disabled-tools.ts:1-19`）实现工具过滤：

```typescript
// src/shared/disabled-tools.ts:3-18
export function filterDisabledTools(
  tools: Record<string, ToolDefinition>,
  disabledTools: readonly string[] | undefined
): Record<string, ToolDefinition> {
  if (!disabledTools || disabledTools.length === 0) {
    return tools
  }

  const disabledToolSet = new Set(disabledTools)
  const filtered: Record<string, ToolDefinition> = {}
  for (const [toolName, toolDefinition] of Object.entries(tools)) {
    if (!disabledToolSet.has(toolName)) {
      filtered[toolName] = toolDefinition
    }
  }
  return filtered
}
```

过滤发生在工具注册的最后阶段，确保被禁用的工具不会暴露给 LLM。此外，`max_tools` 配置（`src/plugin/tool-registry.ts:159-184`）提供了第二层保护，当工具数量超过预算时会自动裁剪低优先级工具。

## 工具执行流程

工具执行遵循 before → execute → after 的三阶段钩子链：

```
┌─────────────────────────────────────────────────────────────────┐
│                     Tool Execution Flow                         │
├─────────────────────────────────────────────────────────────────┤
│  Phase 1: BEFORE (src/plugin/tool-execute-before.ts)            │
│  ├─ writeExistingFileGuard: 防止覆盖已有文件                    │
│  ├─ questionLabelTruncator: 截断过长的标签                      │
│  ├─ claudeCodeHooks: Claude Code 兼容钩子                       │
│  ├─ commentChecker: 检查 AI 风格注释                            │
│  ├─ rulesInjector: 注入规则文件                                 │
│  ├─ tasksTodowriteDisabler: 禁用特定 TODO 写入                  │
│  └─ ... (共 12+ 个 before 钩子)                                 │
├─────────────────────────────────────────────────────────────────┤
│  Phase 2: EXECUTE (ToolDefinition.execute)                      │
│  ├─ 参数校验 (Zod schema)                                       │
│  ├─ 实际业务逻辑执行                                            │
│  └─ 返回执行结果                                                │
├─────────────────────────────────────────────────────────────────┤
│  Phase 3: AFTER (src/plugin/tool-execute-after.ts)              │
│  ├─ toolOutputTruncator: 截断过长输出                           │
│  ├─ commentChecker: 再次检查注释                                │
│  ├─ contextWindowMonitor: 监控上下文窗口                        │
│  ├─ editErrorRecovery: 编辑错误恢复                             │
│  ├─ hashlineReadEnhancer: Hashline 读取增强                     │
│  └─ ... (共 15+ 个 after 钩子)                                  │
└─────────────────────────────────────────────────────────────────┘
```

Before 钩子可以修改输入参数，After 钩子可以修改输出结果，形成完整的 AOP 风格拦截链。

## 实战示例

### 示例 1：工具注册流程

当插件初始化时，`createToolRegistry()` 按以下流程组装工具：

```typescript
// 1. 创建需要依赖的工具
const backgroundTools = createBackgroundTools(managers.backgroundManager, ctx.client)
const callOmoAgent = createCallOmoAgent(ctx, managers.backgroundManager, ...)

// 2. 条件创建（基于配置）
const isMultimodalLookerEnabled = !(pluginConfig.disabled_agents ?? []).some(
  (agent) => agent.toLowerCase() === "multimodal-looker",
)
const lookAt = isMultimodalLookerEnabled ? createLookAt(ctx) : null

// 3. 实验性工具（默认启用）
const taskSystemEnabled = pluginConfig.experimental?.task_system ?? true
const taskToolsRecord = taskSystemEnabled
  ? { task_create, task_get, task_list, task_update }
  : {}

// 4. 合并并过滤
const allTools = { ...builtinTools, ...backgroundTools, ... }
const filteredTools = filterDisabledTools(allTools, pluginConfig.disabled_tools)
```

### 示例 2：工具调用与钩子执行

当 LLM 调用 `task` 工具时，完整的执行流程：

```
1. OpenCode 路由到 tool.execute.before 处理器
2. 执行 12+ 个 before 钩子：
   - rulesInjector: 注入 .sisyphus/rules/ 下的规则
   - commentChecker: 检查 prompt 中的 AI 风格注释
   - directoryAgentsInjector: 注入目录级 AGENTS.md

3. 调用 task.execute()：
   - 解析 category/subagent_type
   - 解析 load_skills
   - 构建 systemContent
   - 决定 sync/background 执行模式

4. 执行 tool.execute.after 钩子：
   - toolOutputTruncator: 截断过长输出
   - contextWindowMonitor: 监控上下文使用
   - categorySkillReminder: 注入分类/技能提醒

5. 返回结果给 LLM
```
