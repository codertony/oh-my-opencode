# 权限层：工具守卫与安全边界

> 所属模块：01-harness-architecture | 三层模型：Layer 3 | 优先级：P0

---

## 架构位置

权限层位于 Harness 三层模型的最顶层（Layer 3），负责在工具执行前后进行安全检查和策略注入。

```
┌─────────────────────────────────────────────────────────────┐
│                    Layer 3: 权限层                           │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │ 12个工具守卫 │  │ Agent权限控制 │  │ 规则注入器         │  │
│  │   钩子      │  │             │  │ (rulesInjector)    │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│                    Layer 2: 工具层                           │
│         26个内置工具 + MCP工具 + 自定义工具                   │
├─────────────────────────────────────────────────────────────┤
│                    Layer 1: 会话层                           │
│         上下文管理、模型回退、会话恢复                        │
└─────────────────────────────────────────────────────────────┘
```

权限层通过 OpenCode SDK 的 `tool.execute.before` 和 `tool.execute.after` 钩子介入工具调用流程，实现细粒度的访问控制。

---

## 核心职责

权限层的核心职责是建立安全边界，确保 Agent 在授权范围内操作。它通过三层机制实现：

**1. 工具守卫钩子（Tool Guard Hooks）**
在工具执行前后插入检查逻辑，包括代码质量检查、文件操作验证、错误恢复等。这些钩子以管道方式串联，每个钩子可以修改输入参数或阻止执行。

**2. Agent 权限配置（Agent Permissions）**
为每个 Agent 定义允许/禁止的工具列表。权限值采用三级模型：`ask`（询问用户）、`allow`（允许）、`deny`（拒绝）。通过 `createAgentToolRestrictions()` 和 `createAgentToolAllowlist()` 函数生成权限配置。

**3. 动态规则注入（Rules Injection）**
根据文件路径自动注入相关的 AGENTS.md 规则文件，确保 Agent 在操作特定目录时遵循该目录的编码规范。

权限层的设计理念是"默认拒绝，显式允许"——未明确授权的工具默认被拒绝访问，必须通过权限配置显式声明才能使用。

### 2. writeExistingFileGuard

**职责**：防止 Agent 在未读取文件的情况下直接覆盖已有文件，强制"先读后写"原则。

**触发时机**：`tool.execute.before`

**代码引用**：
```typescript
// src/hooks/write-existing-file-guard/hook.ts:159-238
return {
  "tool.execute.before": async (input, output) => {
    const toolName = input.tool?.toLowerCase()
    if (toolName !== "write" && toolName !== "read") return

    if (toolName === "read") {
      registerReadPermission(input.sessionID, canonicalPath)
      return
    }
    // 检查是否有读取权限...
    if (!consumeReadPermission(input.sessionID, canonicalPath)) {
      throw new Error("File already exists. Use edit tool instead.")
    }
  }
}
```

## 权限守卫机制

权限检查遵循以下流程：

```
┌────────────────────────────────────────────────────────────────┐
│                     权限检查流程                                 │
├────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 用户请求 ───────┐                                           │
│                     ▼                                           │
│  2. Agent选择 ──────┐                                           │
│                     ▼                                           │
│  3. 加载Agent配置 ──┐                                           │
│                     ▼                                           │
│  4. 应用权限限制 ───┐                                           │
│     ├─ 检查permission字段                                        │
│     ├─ 应用deny列表                                              │
│     └─ 应用allow列表（白名单模式）                                │
│                     ▼                                           │
│  5. 工具调用 ───────┐                                           │
│                     ▼                                           │
│  6. 守卫钩子检查 ───┐                                           │
│     ├─ tool.execute.before                                       │
│     │   ├─ rulesInjector（注入规则）                            │
│     │   ├─ writeExistingFileGuard（文件守卫）                   │
│     │   └─ tasksTodowriteDisabler（任务系统冲突检查）            │
│     ▼                                                           │
│     ├─ 执行工具                                                  │
│     ▼                                                           │
│     ├─ tool.execute.after                                        │
│     │   ├─ commentChecker（注释检查）                           │
│     │   ├─ hashlineReadEnhancer（哈希增强）                     │
│     │   ├─ jsonErrorRecovery（错误恢复）                        │
│     │   └─ readImageResizer（图片处理）                         │
│                     ▼                                           │
│  7. 返回结果 ────────────────────────────────────────────────▶  │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

### 权限值优先级

当多个权限规则冲突时，按以下优先级解析：

1. **显式 deny** - 最高优先级，始终拒绝
2. **显式 allow** - 次高优先级，允许访问
3. **默认 ask** - 询问用户决定
4. **通配符 `*`** - 默认规则，通常设为 deny

## 关键代码片段

### 片段 1：权限配置生成

```typescript
// src/shared/permission-compat.ts:6-40

export type PermissionValue = "ask" | "allow" | "deny"

export interface PermissionFormat {
  permission: Record<string, PermissionValue>
}

/**
 * 创建工具拒绝列表 - 指定工具设为 deny
 */
export function createAgentToolRestrictions(
  denyTools: string[]
): PermissionFormat {
  return {
    permission: Object.fromEntries(
      denyTools.map((tool) => [tool, "deny" as const])
    ),
  }
}

/**
 * 创建工具白名单 - 只允许指定工具，其他全部 deny
 */
export function createAgentToolAllowlist(
  allowTools: string[]
): PermissionFormat {
  return {
    permission: {
      "*": "deny" as const,  // 默认拒绝所有
      ...Object.fromEntries(
        allowTools.map((tool) => [tool, "allow" as const])
      ),
    },
  }
}
```

### 片段 2：Prometheus 文件限制

```typescript
// src/hooks/prometheus-md-only/hook.ts:12-82

export function createPrometheusMdOnlyHook(ctx: PluginInput) {
  return {
    "tool.execute.before": async (input, output) => {
      const agentName = await getAgentFromSession(input.sessionID, ...)
      
      if (!isPrometheusAgent(agentName)) return

      const toolName = input.tool
      
      // 允许 task 工具，但注入警告
      if (TASK_TOOLS.includes(toolName)) {
        const prompt = output.args.prompt as string
        if (prompt && !prompt.includes(SYSTEM_DIRECTIVE_PREFIX)) {
          output.args.prompt = PLANNING_CONSULT_WARNING + prompt
        }
        return
      }

      // 检查是否为允许的文件路径
      const filePath = output.args.filePath ?? output.args.path
      if (!isAllowedFile(filePath, ctx.directory)) {
        throw new Error(
          `[prometheus-md-only] Prometheus can only write to .sisyphus/*.md`
        )
      }
    },
  }
}
```

## 实战示例

### 示例：Oracle Agent 的只读限制

当用户尝试让 Oracle Agent 修改文件时：

1. **Agent 配置阶段**：Oracle 的权限配置包含 `write: "deny"`
   ```typescript
   // src/agents/oracle.ts:246-251
   const restrictions = createAgentToolRestrictions([
     "write", "edit", "apply_patch", "task"
   ])
   ```

2. **工具调用拦截**：当 Oracle 尝试调用 Write 工具时，OpenCode SDK 根据 permission 配置直接拒绝

3. **错误反馈**：Agent 收到权限错误，提示用户该 Agent 为只读模式

4. **替代方案**：Oracle 会建议使用其他 Agent（如 Hephaestus）或工具来完成修改操作

### 示例：Hashline 增强的实际效果

启用 `hashline_edit` 后，Read 工具输出格式变化：

```
// 原始输出
11: function hello() {
22:   return "world"
33: }

// Hashline 增强后
11#VK| function hello() {
22#XJ|   return "world"
33#MB| }
```

Agent 可以使用 `11#VK` 作为稳定引用进行编辑，即使文件内容发生变化，哈希不匹配也会阻止错误的编辑操作。
