上下文组装机制位于 Harness 的第三层，负责在消息进入 LLM 之前自动注入相关上下文。它是连接项目文档与 AI 代理的桥梁，确保代理始终拥有完成任务所需的背景信息。

## 核心职责

上下文组装机制的核心职责是**在合适的时机将正确的上下文注入到对话中**。这包括四个主要方面：

**1. 自动发现与注入**
当代理读取、编辑或写入文件时，系统会自动向上遍历目录树，查找并注入相关的 AGENTS.md 和 README.md 文件。这种机制确保代理在处理特定模块时能够获取该模块的上下文说明。

**2. 条件规则匹配**
通过 glob 模式匹配，系统可以有条件地注入规则文件。例如，当处理前端组件时自动注入 UI/UX 规范，处理后端 API 时自动注入架构约束。

**3. 上下文压缩恢复**
当会话触发上下文压缩（compaction）后，系统会自动恢复关键的代理配置和工具设置，确保压缩后的会话不会丢失重要的执行上下文。

**4. 去重与截断**
所有注入的上下文都会经过智能去重（基于内容哈希和真实路径）和动态截断，避免重复注入相同内容，同时根据模型上下文窗口大小自动调整注入内容的长度。

## 4 种注入类型

### 1. AGENTS.md 自动注入

AGENTS.md 自动注入是 Oh My OpenAgent 的核心特性之一。当代理执行文件操作（read/write/edit/multiedit）时，系统会自动查找并注入相关目录的 AGENTS.md 文件。

**工作原理：**

```typescript
// src/hooks/directory-agents-injector/finder.ts:12-38
export function findAgentsMdUp(input: {
  startDir: string;
  rootDir: string;
}): string[] {
  const found: string[] = [];
  let current = input.startDir;

  while (true) {
    // 跳过根目录的 AGENTS.md（OpenCode 系统已加载）
    const isRootDir = current === input.rootDir;
    if (!isRootDir) {
      const agentsPath = join(current, AGENTS_FILENAME);
      if (existsSync(agentsPath)) {
        found.push(agentsPath);
      }
    }

    if (isRootDir) break;
    const parent = dirname(current);
    if (parent === current) break;
    if (!parent.startsWith(input.rootDir)) break;
    current = parent;
  }

  return found.reverse(); // 最近的最先
}
```

**目录遍历逻辑：**
- 从目标文件所在目录开始向上遍历
- 跳过项目根目录的 AGENTS.md（避免与 OpenCode 系统加载重复）
- 收集所有找到的 AGENTS.md 文件路径
- 按距离排序（最近的优先）

### 2. README.md 自动注入

README.md 注入与 AGENTS.md 注入机制类似，但针对的是项目说明文档。当代理首次接触某个目录时，README.md 提供了该目录的概览信息。

**注入流程：**

```typescript
// src/hooks/directory-readme-injector/injector.ts:21-59
export async function processFilePathForReadmeInjection(input: {
  ctx: PluginInput;
  truncator: DynamicTruncator;
  sessionCaches: Map<string, Set<string>>;
  filePath: string;
  sessionID: string;
  output: { title: string; output: string; metadata: unknown };
}): Promise<void> {
  const resolved = resolveFilePath(input.ctx.directory, input.filePath);
  if (!resolved) return;

  const dir = dirname(resolved);
  const cache = getSessionCache(input.sessionCaches, input.sessionID);
  const readmePaths = findReadmeMdUp({ startDir: dir, rootDir: input.ctx.directory });

  let dirty = false;
  for (const readmePath of readmePaths) {
    const readmeDir = dirname(readmePath);
    if (cache.has(readmeDir)) continue; // 会话级去重

    try {
      const content = readFileSync(readmePath, "utf-8");
      const { result, truncated } = await input.truncator.truncate(
        input.sessionID,
        content,
      );
      // 注入到工具输出中
      input.output.output += `\n\n[Project README: ${readmePath}]\n${result}${truncationNotice}`;
      cache.add(readmeDir);
      dirty = true;
    } catch {}
  }

  if (dirty) {
    saveInjectedPaths(input.sessionID, cache);
  }
}
```

### 3. 条件规则注入

条件规则注入允许基于文件路径模式（glob）动态注入规则。这通过 `rulesInjectorHook` 实现，支持从 AGENTS.md、.rules 文件或配置中加载规则。

**Pattern Matching 机制：**

```typescript
// src/hooks/rules-injector/matcher.ts:14-42
export function shouldApplyRule(
  metadata: RuleMetadata,
  currentFilePath: string,
  projectRoot: string | null
): MatchResult {
  if (metadata.alwaysApply === true) {
    return { applies: true, reason: "alwaysApply" }
  }

  const globs = metadata.globs
  if (!globs) {
    return { applies: false }
  }

  const patterns = Array.isArray(globs) ? globs : [globs]
  if (patterns.length === 0) {
    return { applies: false }
  }

  const relativePath = projectRoot ? relative(projectRoot, currentFilePath) : currentFilePath

  for (const pattern of patterns) {
    if (picomatch.isMatch(relativePath, pattern, { dot: true, bash: true })) {
      return { applies: true, reason: `glob: ${pattern}` }
    }
  }

  return { applies: false }
}
```

**规则优先级：**
1. 同一目录的规则文件优先
2. 父目录的规则次之
3. 距离越近优先级越高
4. 相同距离的规则全部注入

### 4. 上下文压缩恢复注入

当会话触发上下文压缩（compaction）时，部分代理配置和工具设置可能会丢失。压缩恢复注入机制会在压缩后自动恢复这些关键配置。

**恢复逻辑：**

```typescript
// src/hooks/compaction-context-injector/recovery.ts:26-132
const recoverCheckpointedAgentConfig = async (
  sessionID: string,
  reason: "session.compacted" | "no-text-tail",
): Promise<boolean> => {
  if (!ctx) {
    return false
  }

  const checkpoint = getCompactionAgentConfigCheckpoint(sessionID)
  if (!checkpoint?.agent) {
    return false
  }

  const tailState = getTailState(sessionID)
  const now = Date.now()
  if (tailState.lastRecoveryAt && now - tailState.lastRecoveryAt < RECOVERY_COOLDOWN_MS) {
    return false // 冷却期内不重复恢复
  }

  const currentPromptConfig = await resolveSessionPromptConfig(ctx, sessionID)
  const validatedCheckpointModel = validateCheckpointModel(
    checkpoint.model,
    currentPromptConfig.model,
  )

  // 恢复代理配置
  await ctx.client.session.promptAsync({
    path: { id: sessionID },
    body: {
      noReply: true,
      agent: expectedPromptConfig.agent,
      ...(model ? { model } : {}),
      ...(tools ? { tools } : {}),
      parts: [createInternalAgentTextPart(AGENT_RECOVERY_PROMPT)],
    },
    query: { directory: ctx.directory },
  })

  // 更新会话状态
  updateSessionAgent(sessionID, expectedPromptConfig.agent)
  if (model) {
    setSessionModel(sessionID, model)
  }
  if (tools) {
    setSessionTools(sessionID, tools)
  }

  return true
}
```

**触发条件：**
- `session.compacted` 事件触发
- 检测到连续无文本消息（no-text-tail）且近期发生过压缩

## 注入触发条件

上下文注入在以下时机触发：

| 触发时机 | 注入类型 | 说明 |
|----------|----------|------|
| `tool.execute.before` | AGENTS.md, README.md, Rules | 文件操作前注入相关上下文 |
| `tool.execute.after` | AGENTS.md, README.md, Rules | 文件操作后补充上下文 |
| `chat.message` | Pending Context | 新消息时注入待处理的上下文 |
| `experimental.chat.messages.transform` | Synthetic Parts | 消息转换阶段插入合成内容 |
| `session.compacted` | Compaction Recovery | 压缩后恢复代理配置 |

**工具级触发（Tool Guard Hooks）：**
- 仅对特定工具触发：`["read", "write", "edit", "multiedit"]`
- 从工具输出中提取文件路径
- 基于路径查找相关上下文

**消息级触发（Transform Hooks）：**
- 在消息发送到 LLM 前触发
- 查找最后一条用户消息
- 插入合成 part 包含待注入上下文

## 关键代码片段

### 片段 1：上下文收集器的注册与合并

```typescript
// src/features/context-injector/collector.ts:19-67
export class ContextCollector {
  private sessions: Map<string, Map<string, ContextEntry>> = new Map()

  register(sessionID: string, options: RegisterContextOptions): void {
    if (!this.sessions.has(sessionID)) {
      this.sessions.set(sessionID, new Map())
    }

    const sessionMap = this.sessions.get(sessionID)!
    const key = `${options.source}:${options.id}`

    const entry: ContextEntry = {
      id: options.id,
      source: options.source,
      content: options.content,
      priority: options.priority ?? "normal",
      registrationOrder: ++registrationCounter,
      metadata: options.metadata,
    }

    sessionMap.set(key, entry)
  }

  consume(sessionID: string): PendingContext {
    const pending = this.getPending(sessionID)
    this.clear(sessionID)
    return pending
  }
}
```

### 片段 2：消息转换阶段的上下文注入

```typescript
// src/features/context-injector/injector.ts:86-166
export function createContextInjectorMessagesTransformHook(
  collector: ContextCollector
): MessagesTransformHook {
  return {
    "experimental.chat.messages.transform": async (_input, output) => {
      const { messages } = output
      if (messages.length === 0) return

      // 查找最后一条用户消息
      let lastUserMessageIndex = -1
      for (let i = messages.length - 1; i >= 0; i--) {
        if (messages[i].info.role === "user") {
          lastUserMessageIndex = i
          break
        }
      }

      if (lastUserMessageIndex === -1) return

      const lastUserMessage = messages[lastUserMessageIndex]
      const sessionID = getMainSessionID()
      
      if (!collector.hasPending(sessionID)) return

      const pending = collector.consume(sessionID)
      if (!pending.hasContent) return

      // 创建合成 part
      const syntheticPart = {
        id: `synthetic_hook_${sessionID}`,
        messageID: lastUserMessage.info.id,
        sessionID: sessionID,
        type: "text" as const,
        text: pending.merged,
        synthetic: true,  // 在 UI 中隐藏
      }

      // 插入到用户消息中
      lastUserMessage.parts.splice(textPartIndex, 0, syntheticPart as Part)
    },
  }
}
```

## 实战示例

### 示例：处理前端组件时的上下文注入

假设代理正在处理 `src/components/Button.tsx`：

**步骤 1：文件读取触发**
```
User: 请优化 Button 组件的性能
```

**步骤 2：系统查找相关上下文**
```
查找路径：src/components/Button.tsx
├── src/components/AGENTS.md      ← 找到（组件级规范）
├── src/AGENTS.md                 ← 找到（项目级规范）
└── AGENTS.md                     ← 跳过（根目录，系统已加载）
```

**步骤 3：条件规则匹配**
```
文件路径匹配：src/components/Button.tsx
├── glob: "**/*.tsx"              ← 匹配，注入 TS 规范
├── glob: "src/components/**"     ← 匹配，注入组件规范
└── glob: "**/*.{css,scss}"       ← 不匹配，跳过样式规则
```

**步骤 4：注入到上下文**
```markdown
[Directory Context: src/components/AGENTS.md]
# src/components/AGENTS.md

所有组件必须：
1. 使用函数式组件
2. 支持 forwardRef
3. 包含完整的 JSDoc 注释

---

[Directory Context: src/AGENTS.md]
# src/AGENTS.md

项目使用 React 18 + TypeScript 5.0
测试框架：Vitest
样式方案：Tailwind CSS

---

[Rule: .rules/typescript.md]
[Match: glob: **/*.tsx]
TypeScript 规范：
- 严格模式启用
- 禁止使用 any
- 接口命名使用 I 前缀
```

**步骤 5：代理基于完整上下文工作**
代理现在了解了组件规范、项目技术栈和 TypeScript 规则，可以给出符合项目标准的优化建议。
