## 核心职责

安全守卫是 Harness 架构中的关键防护机制，负责在工具执行前后进行安全检查、错误恢复和权限控制。其核心职责包括三个方面：

**循环中断机制**：防止代理陷入无限循环或重复执行无效操作。通过检测任务停滞、连续失败和未完成待办事项，系统能够智能判断何时需要中断当前执行流程，避免资源浪费和上下文膨胀。

**错误恢复机制**：在工具执行失败时提供自动化的恢复策略。包括 Edit 工具错误检测、JSON 解析错误修复、空任务响应处理等，确保代理能够从错误状态中快速恢复并继续执行任务。

**权限守卫机制**：控制代理对文件系统和敏感操作的访问权限。通过读取权限追踪、文件覆盖保护和工具白名单/黑名单机制，防止意外的数据损坏或未授权操作。

## 安全守卫机制

### 1. 循环中断机制

循环中断机制通过多层检测防止代理陷入无限循环：

**待办续期执行器 (Todo Continuation Enforcer)**：当会话进入空闲状态且存在未完成的待办事项时，系统会触发续期机制。该机制包含以下保护：

- **失败计数器**：连续失败达到 5 次后暂停 5 分钟
- **冷却期**：基础冷却 30 秒，每次失败后指数增长
- **中止检测**：检测到中止信号后 3 秒内不触发续期
- **停滞检测**：跟踪待办完成进度，无进展时停止续期

```typescript
// src/hooks/todo-continuation-enforcer/idle-event.ts:111-130
if (state.consecutiveFailures >= MAX_CONSECUTIVE_FAILURES) {
  log(`[${HOOK_NAME}] Skipped: max consecutive failures reached`, 
    { sessionID, consecutiveFailures: state.consecutiveFailures })
  return
}

const effectiveCooldown =
  CONTINUATION_COOLDOWN_MS * Math.pow(2, Math.min(state.consecutiveFailures, 5))
if (state.lastInjectedAt && Date.now() - state.lastInjectedAt < effectiveCooldown) {
  log(`[${HOOK_NAME}] Skipped: cooldown active`, 
    { sessionID, effectiveCooldown, consecutiveFailures: state.consecutiveFailures })
  return
}
```

### 2. 错误恢复

错误恢复机制在工具执行失败时提供自动化的修复策略：

**Edit 错误恢复**：检测常见的 Edit 工具错误模式并注入恢复提示：

```typescript
// src/hooks/edit-error-recovery/hook.ts:6-28
export const EDIT_ERROR_PATTERNS = [

  "oldString not found",
  "oldString found multiple times",
] as const

export const EDIT_ERROR_REMINDER = `
[EDIT ERROR - IMMEDIATE ACTION REQUIRED]

You made an Edit mistake. STOP and do this NOW:

1. READ the file immediately to see its ACTUAL current state
2. VERIFY what the content really looks like (your assumption was wrong)
3. APOLOGIZE briefly to the user for the error
4. CONTINUE with corrected action based on the real file content
`
```

**空任务响应检测**：当子代理任务返回空响应时，系统会注入警告信息，防止代理无限等待：

```typescript

- Returned an empty result

```

### 3. 权限守卫

权限守卫机制控制代理对文件系统和敏感操作的访问：

**文件写入守卫**：防止代理在未读取文件的情况下覆盖现有文件：

```typescript
// src/hooks/write-existing-file-guard/hook.ts:159-238
"tool.execute.before": async (input, output) => {
  const toolName = input.tool?.toLowerCase()
  if (toolName !== "write" && toolName !== "read") {
    return
  }

  // 读取操作：记录读取权限
  if (toolName === "read") {
    if (!existsSync(resolvedPath) || !input.sessionID) {
      return
    }
    registerReadPermission(input.sessionID, canonicalPath)
    return
  }

  // 写入操作：检查是否有读取权限
  if (input.sessionID && consumeReadPermission(input.sessionID, canonicalPath)) {
    log("[write-existing-file-guard] Allowing overwrite after read", {...})
    invalidateOtherSessions(canonicalPath, input.sessionID)
    return
  }

  throw new Error("File already exists. Use edit tool instead.")
}
```

**工具权限系统**：通过权限配置控制代理可用的工具：

```typescript
// src/shared/permission-compat.ts:15-40
export function createAgentToolRestrictions(
  denyTools: string[]
): PermissionFormat {
  return {
    permission: Object.fromEntries(
      denyTools.map((tool) => [tool, "deny" as const])
    ),
  }
}

export function createAgentToolAllowlist(
  allowTools: string[]
): PermissionFormat {
  return {
    permission: {
      "*": "deny" as const,
      ...Object.fromEntries(
        allowTools.map((tool) => [tool, "allow" as const])
      ),
    },
  }
}
```

## 安全守卫流程

安全守卫的工作流程分为三个阶段：

1. **前置检查 (tool.execute.before)**：在工具执行前进行权限验证、参数检查和规则注入
2. **工具执行**：执行实际的工具操作
3. **后置处理 (tool.execute.after)**：检查结果、注入恢复提示、执行清理操作

## 依赖关系

安全守卫模块依赖以下组件：

- **Hook 系统**：提供 `tool.execute.before` 和 `tool.execute.after` 事件钩子

- **日志系统**：记录守卫决策和错误信息

## 实战示例

### 示例 1: 无限循环检测

场景：代理在修复一个 bug 时反复尝试相同的 Edit 操作，每次都失败。

```typescript
// 系统检测到连续失败
// src/hooks/todo-continuation-enforcer/idle-event.ts:120-123
if (state.consecutiveFailures >= MAX_CONSECUTIVE_FAILURES) {
  log(`[${HOOK_NAME}] Skipped: max consecutive failures reached`, 
    { sessionID, consecutiveFailures: state.consecutiveFailures })
  return  // 停止续期，防止无限循环
}

// 同时 Edit 错误恢复钩子注入提示
// src/hooks/edit-error-recovery/hook.ts:48-55
const hasEditError = EDIT_ERROR_PATTERNS.some((pattern) =>
  outputLower.includes(pattern.toLowerCase())
)

if (hasEditError) {
  output.output += `\n${EDIT_ERROR_REMINDER}`
}
```

**结果**：代理收到错误恢复提示，重新读取文件后成功修复问题。

### 示例 2: 权限守卫触发

场景：代理尝试直接覆盖一个从未读取过的配置文件。

```typescript
// src/hooks/write-existing-file-guard/hook.ts:221-237
if (input.sessionID && consumeReadPermission(input.sessionID, canonicalPath)) {
  // 允许写入，因为已经读取过
  log("[write-existing-file-guard] Allowing overwrite after read", {...})
  invalidateOtherSessions(canonicalPath, input.sessionID)
  return
}

// 没有读取权限，阻止写入
log("[write-existing-file-guard] Blocking write to existing file", {...})
throw new Error("File already exists. Use edit tool instead.")
```

**结果**：系统抛出错误，提示代理先读取文件再使用 Edit 工具修改，防止意外的数据丢失。
